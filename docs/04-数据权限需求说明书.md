## 一、三级数据范围定义与组织口径

### 1.1 三级范围精确定义

| 编码 | 名称 | 定义 |
| --- | --- | --- |
| SELF | 本人 | 仅「归属人」为当前用户本人的记录可见/可操作 |
| GRADE | 本年级 | 当前用户所属组织节点（年级/教研组/处室）辖内全部成员的记录可见/可操作 |
| ALL | 全校 | 全校全部记录可见/可操作 |

> 关系：SELF < GRADE < ALL，为严格递增的包含关系。

### 1.2 「本年级」的判定口径（三种组织统一到部门树）

行政年级、教研组（学科组）、行政部门（处室）统一为部门树（REQ-E4）的「部门节点」，用类型字段区分：

| deptType | 含义 | 示例 |
| --- | --- | --- |
| SCHOOL | 根节点（学校） | 某中学 |
| GRADE | 行政年级 | 七年级/八年级/九年级；高一/高二/高三 |
| CLASS | 班级 | 七(1)班 / 高一(3)班 |
| SUBJECT | 教研组（学科组） | 语文组/数学组 |
| OFFICE | 行政处室 | 总务处/教务处/德育处/办公室 |

- 用户可挂靠 1..N 个部门节点（user_dept 关联表）。
- 教研组（SUBJECT）挂在行政年级（GRADE）节点下作为子孙节点；班级（CLASS）也挂在行政年级（GRADE）节点下作为子孙节点；处室（OFFICE）挂在根节点（SCHOOL）下。
- 学生以班级（CLASS）作为其挂靠的组织节点；班主任通过 `head_teacher.classId` 绑定其担任班主任的班级。

### 1.3 一条记录如何判定"属于哪个年级 / 哪个班级"

记录创建时落两个归属字段：`归属人ID` + `归属部门ID`。
- 归属部门ID 直接取自归属人创建时的主挂靠部门。
- 判定"本年级"时：取归属人 → 沿部门树向上找第一个 `deptType=GRADE` 节点 → 该节点即"行政年级"。
- 年级组长（挂 GRADE 节点）看"本年级"数据 = 该 GRADE 节点及其全部子孙节点下成员产生的记录。

**「本班」载体判定（班主任，仅适用于学生相关数据）：**
- 班主任数据范围**级别仍为「本年级」**，但通过 `head_teacher.classId` 把实际可见范围收窄到其所带 CLASS 节点。
- 判定：班主任查学生记录时，取该学生挂靠的 CLASS 节点，若 `studentClassId == head_teacher.classId` → 允许；否则拒绝。
- 即「本班」不是第四级权限级别，而是「本年级」级别 + CLASS 组织载体的组合（同「本组」先例，见 §1.2）。
- **适用域边界【B7】**：「本班」载体**仅适用于学生相关数据**（德育请假/违纪/评优、体育体测/训练队）；教务调课/代课、后勤领用/报修等**教师个人事务仍按「本人」**，不套「本班」。
- **换届快照【E3】**：「本班」判定按**记录产生时的班主任**（记录落 `classId + 学期` 快照），不随班主任换届实时变化——新班主任看新学期本班数据，历史数据归属原班主任/原班级。

### 1.4 全校公共数据（不套三级）

以下数据不参与 SELF/GRADE/ALL 记录级过滤，仅由「菜单/按钮权限」控制访问：
库存台账（可领用列表）、菜单、角色、部门树、状态字典、故障类型字典、审批流模板、违纪处分等级字典、评选标准（只读部分）。

### 1.5 关系型归属（家长-子女，德育域新增）

- 家长与学生为**多对多**关系，建关联表 `student_parent(studentId, parentUserId)`。
- 家长角色数据范围 = **SELF 的关系型扩展**：仅能访问「其关联子女」的记录，**不通过部门树判定**。
- 判定：家长查询某学生记录时，先校验 `student_parent` 是否存在 `(parentUserId=当前家长, studentId=目标学生)`，存在才放行；否则 40304（防枚举）。
- 一个家长多子女时，其可见范围 = 全部关联子女记录的**并集**。
- 学生本人数据范围 = SELF，判定 `studentId == 当前学生用户ID`。

### 1.6 资产台账 asset（统一数据对象，跨后勤/科教/体育）

**结论**：后勤物资、科教实验器材、体育器材三处**合并为一个统一「资产台账(asset)」**数据对象，借还/库存模型一致；三域业务场景各自独立（领用审批 / 实验预约 / 体育借用），仅底层台账与库存数据对象统一。

**属性**：
| 字段 | 含义 |
| --- | --- |
| id | 资产唯一标识 |
| name | 资产名称 |
| assetType | 类型：物资 / 实验器材 / 体育器材（**中文为显示名，由 DICT-* 字典提供**；英文码值见 docs/02 §1.7 枚举码值约定：`MATERIAL` / `LAB_EQUIP` / `SPORT_EQUIP`；**库内与 API 一律用英文码**） |
| quantity | 总数量 |
| availableQty | 可借/可领用数量 |
| status | 状态：在库 / 借出 / 报修 / 报废（**中文为显示名**；码值：`IN_STOCK` / `LENT` / `REPAIRING` / `SCRAPPED`；**库内与 API 一律用英文码**） |
| location | 存放点 |

**归属口径**：asset 为**全校共享**数据对象，不按 SELF/GRADE/ALL 做记录级归属过滤；不同角色的可借/可领用范围由「各域业务场景的借用/领用权限 + 菜单/按钮权限」控制。库存变更（入库/借用/归还）统一走服务端校验（见 §4.2 D 段）。

### 1.7 角色授权型归属（公告 notice，党政办域）

- **公告（notice）不走组织型三级数据范围**，走**角色授权**：发布时选可见角色集合。
- 用户能否看到某公告 = **命中该公告可见角色** + **有公告菜单权限（M1201）**，二者同时满足。
- 这是与「组织型（部门树）」「关系型（家长-子女）」并列的第三种归属类型——**角色授权型**。

### 1.8 学期/学年维度（基础字典，跨域统一）

- 新增基础字典「学年 + 学期」：学年（如 2025-2026）+ 学期（第一学期/第二学期），并维护「当前学期」标识。
- 六域业务数据（请假/违纪/体测/评优/采购/课题/资源/公文等）均关联学期字段；统计默认按「当前学期」聚合。
- 数据大屏「同比」= 与「去年同学期」对比；「环比」= 与「上一学期」对比。
- **统一时间口径**：统计口径统一为「**学期 + 周次**」——数据归属、聚合维度、权限判定一律以学期为准。趋势图与报表须提供「**学期 / 自然月**」**维度切换器**：自然月仅为**展示维度**（兼顾财务月报等阅读习惯），**不改变数据归属范围与权限判定口径**——切换维度不改变任何可见性、聚合结果与越权判定，仅重排展示粒度。
- **术语纪律**：六域不得自造时间维度（如"自定义起止日期""本季度"作为主口径）；确需自然月处须显式标注"仅展示维度"，并在服务端以学期+周次完成聚合与鉴权后再做月粒度重排。

### 1.9 学生账号生命周期

- 学生账号状态：在读 / 毕业 / 转学 / 离校 / 休学。
- 离校处置：停用账号（不可登录）、解除 `student_parent` 关联、数据归档标记（不物理删除）。
- 家长账号与 `student_parent` 随学生离校一并解除。

### 1.10 数据归档策略（通用）

- 往届学生数据、结题课题、归档公文等历史数据：**首版「保留 + 归档标记，不物理删除」**，通过归档标记与当前学期隔离；物理清理策略列未来版本。

### 1.11 统一场地对象（space）

> 六域凡涉及「场地」类资源（教室 / 实验室 / 会议室 / 体育场地），统一归入本对象，不再各域自造概念。可移动实物走「资产台账 asset」（见 §1.6），**场地走 space，二者不得混用**。

- **字段**：`spaceId` / `spaceName` / `spaceType`（`CLASSROOM` 普通教室 | `LAB` 实验室 | `MEETING_ROOM` 会议室 | `SPORT_VENUE` 体育场地）/ `capacity` 容量 / `deptNodeId` 挂靠部门节点（组织型归属载体）/ `status` 状态（可用 / 停用 / 维修中；**中文为显示名**，码值 `AVAILABLE` / `DISABLED` / `REPAIRING`；**库内与 API 一律用英文码**）。
- **归属类型**：**组织型**（挂部门树节点），沿用既有三级数据范围（SELF / GRADE / ALL），不新增第四级。
- **权限矩阵**：见 §3.11。

### 1.12 场地占用约束（排课优先，单向校验）

- **占用来源两类**：①**排课占用**——来自 docs/06 课表（含正式发布版本与已生效的调课/代课结果），**是场地占用的权威来源**；②**预约占用**——来自科教域实验预约（docs/10）、党政办会议室预约（docs/09）、体育域赛事排期（docs/11）。
- **首版单向校验**：预约类请求提交时，服务端**必须先读取该「场地 + 时段」的课表占用做冲突校验**；命中排课占用一律**拒绝并返回 40901（场地已被课表占用）**；未命中则写入预约占用，再按各域既有 C9 并发规则竞争同一格（见各域对应 AC）。
- **反向不做（V2.0）**：**预约不阻断排课**——排课/调课发布时不校验预约占用；若发生重叠，以排课结果为准并**通过消息中心通知受影响预约人**（docs/15）。**双向互斥 / 预约优先策略列 V2.0**。
- **错误码**：沿用既有 4xx 风格，409 段归「资源冲突」类——`40901` 场地被课表占用、`40902` 场地被并发的其他预约占用（竞争失败时返回，见各域 C9 AC）。

## 二、数据权限的配置模型

### 2.1 结论：数据范围是「角色」的属性，不是「用户」的属性

- 角色（REQ-E2）绑定数据范围（SELF/GRADE/ALL），用户通过挂角色获得数据范围，不做逐人配置。
- 预留：`user_role_scope` 可对"用户-角色"关联做范围覆盖，首版默认关闭。

### 2.2 多角色数据范围合并规则

- **取并集（最大范围）**：用户有效数据范围 = MAX(各角色数据范围)，SELF < GRADE < ALL。
- 菜单权限同样取并集。
- 服务端按"实时取角色"计算，不做缓存授权快照（避免权限变更延迟）。

### 2.3 角色数据范围一览（含德育域新增角色）

| 角色 | 数据范围级别 | 组织/关系载体 |
| --- | --- | --- |
| R-ADMIN 系统管理员 | ALL | — |
| R-PRINCIPAL 校长 | ALL | — |
| R-VP 校领导 | ALL | 可按分管域收紧 |
| R-LOGISTICS 后勤主管 | ALL | — |
| R-MORAL 德育处 | ALL | — |
| R-PARTY 党政办 | ALL | — |
| R-GRADE 年级组长 | GRADE | 所挂 GRADE 节点 |
| R-SUBJECT 教研组长 | GRADE（本组） | 所挂 SUBJECT 节点 |
| R-TEACHER 普通教师 | SELF | —（班主任另加 head_teacher.classId → 本班） |
| R-STUDENT 学生 | SELF | studentId == 当前学生 |
| R-PARENT 家长 | SELF（关系型） | student_parent 关联的本人子女 |

| 归还 | 借用人本人（库存回补） |
| 库存调整/报废 | 后勤（R-LOGISTICS）统一管理 |

> **域隔离规则【B5】**：`assetType` 决定可用域——体育器材（assetType=体育器材）仅体育借用流程可借；实验器材（assetType=实验器材）仅科教实验预约可借；物资（assetType=物资）仅后勤领用可借。**首版严格域隔离，不支持跨域借用**（如体育教师借实验器材、科教教师借用体育器材、用后勤物资类比跨域一律不予支持）；服务端按 `assetType × 借用权限点` 双重校验，跨域请求直接拒绝，越权 40302。**跨域借用列未来版本**——届时再定义授权载体（专属菜单 / 临时权限点 / 有效期），首版不引入复杂授权模型，符合单场景闭环策略。
> **并发不超卖【C9】**：`availableQty` 扣减必须保证并发唯一性（数据库原子更新/乐观锁），多人同时借用最后一件仅一人成功，其余返回库存不足。

### 3.10 公告（notice，角色授权型，不套组织型三级）

| 操作 | 权限 |
| --- | --- |
| 查询/已读 | 命中公告可见角色 + 有 M1201 菜单权限（二者同时满足） |
| 发布/撤回 | R-PARTY（党政办） |
| 已读回执查看 | R-PARTY + 校长 |

> **已读状态唯一口径（消解双轨）**：业务对象（公告 / 审批单 / 请假单 / 会议通知等）的「已读」以**业务端记录为准**。用户无论从「通知公告 M1201」还是「消息中心 M0105」任一入口打开该对象，**均由业务端写入同一份已读回执**；消息中心**不独立维护业务对象的已读计数**，仅维护站内信自身的已读/未读用于未读角标（见 docs/15 AC-MS8-1、docs/09 REQ-L2）。「公告已读率」等回执类指标统一取业务端口径，避免双轨不同步导致校长端硬指标①失真。

### 3.11 统一场地对象 space（组织型，套三级）

| 操作 | R-ADMIN | R-PRINCIPAL / R-VP | R-LOGISTICS（场地设施归口） | R-TEACHER / R-GRADE / R-SUBJECT | R-STUDENT | R-PARENT |
| --- | --- | --- | --- | --- | --- | --- |
| 查询可预约场地 | 全校 | 全校只读 | 全校 | 开放范围内（组织型：本人可见且可预约） | 仅本人课表相关场地 | — |
| 发起预约占用 | 全校 | 全校 | 全校 | 开放范围内 + 须过 §1.12 课表占用校验（命中返 40901） | 限随课场景 | — |
| 场地基础数据维护（增删改） | 全校 | — | 全校 | — | — | — |
| 停用/启用场地 | 全校 | — | 全校 | — | — | — |

> **归属说明**：space 为**组织型**（挂 `deptNodeId` 部门树节点），沿用 SELF / GRADE / ALL 三级：**SELF**＝本人可见且可预约范围内的场地；**GRADE**＝本年级/本教研组可见范围内的场地；**ALL**＝全校场地。教师与学生的可见/可预约范围由「space 开放范围」字段（该场地对本部门/本年级是否开放）与用户组织归属共同判定，服务端按 §4.1 统一算法兜底，越权 40303。
> **与 asset 的边界**：可移动实物走 asset（§1.6 / §3.9），固定场所走 space（§1.11），**二者互不交叉**。例如「实验器材」属 asset、「实验室」属 space——科教实验预约同时涉及时须分别校验：器材走 C9 库存原子扣减，场地走 §1.12 占用冲突校验。

### 4.1 归属字段约定

| 报修工单 | reporterId | reporterDeptId |

| 审批记录 | 关联对象ID | 继承被审批对象 |
| 异常提醒 | 关联对象ID + 责任人 | 继承 |

> **家长对违纪的可见边界【B4】**：家长仅可见「违纪事实 + 通知」，**不含内部处理意见/谈话记录**；严重处分级（记过/留校察看）需家长确认。服务端对违纪记录按「家长视角字段」过滤，内部字段不下发。

### 4.2 数据范围判定算法（服务端统一实现）

**A. 组织型归属（部门树，SELF/GRADE/ALL）：**
1. 取目标记录的归属人ID。
2. 查归属人挂靠部门，得 deptId。
3. 沿部门树向上，找第一个 `deptType=GRADE` 节点 → `recordGradeNodeId`。
4. 取当前用户挂靠部门，向上找其 `deptType=GRADE` 节点集合 → `userGradeNodeIds`（兼课可多个）。
5. 判定：数据范围=GRADE 且 `recordGradeNodeId ∈ userGradeNodeIds`（或为其子孙）→ 允许；否则拒绝。
6. 数据范围=ALL 直接放行；数据范围=SELF 仅当 `归属人ID == 当前用户ID` 放行。

**B. 「本班」载体判定（班主任，德育域）：**
7. 若当前用户具备 `head_teacher.classId`（班主任身份）且数据范围级别=本年级，则其可见范围收窄为：目标学生的 `studentClassId == head_teacher.classId` → 允许；否则拒绝。
8. 非班主任教师（无 `head_teacher.classId`）对学生记录无「本班」可见性。

**C. 关系型归属判定（家长-子女，德育域）：**
9. 家长角色数据范围=关系型 SELF，判定：`student_parent` 存在 `(parentUserId=当前家长, studentId=目标学生)` → 允许；否则 40304（防枚举）。
10. 多子女取并集：`parentUserId` 关联的全部 `studentId` 记录均可见。
11. 学生本人数据范围=SELF，判定 `studentId == 当前学生用户ID`。

**D. 资产台账 asset 判定（借用/归还权限 + 库存变更校验）：**
12. asset 为全校共享，不按 SELF/GRADE/ALL 过滤记录；可借/可领用范围由「各域借用场景 + 菜单/按钮权限」控制。
13. 借用/领用：校验当前用户是否命中该资产所属域的借用/领用权限点（BTN-MAT-APPLY / 实验预约 / BTN-SPORT-EQUIP-BORROW），**且资产 `assetType` 与借用域匹配（域隔离，见 §3.9）**，且 `availableQty > 0`，通过才允许并扣减 `availableQty`。
14. 归还：仅借用人本人可归还，归还后回补 `availableQty`。
15. 库存变更（入库/调整/报废）仅后勤（R-LOGISTICS）或流程配置的入库角色可执行，服务端校验，越权返回 40302。
16. **并发不超卖【C9】**：`availableQty` 扣减以数据库原子更新（`UPDATE ... WHERE availableQty>0`）或乐观锁保证唯一性，多人并发借用最后一件仅一人成功。
17. **超期未归还预警【C10】**：资产借用超过约定归还期未归还，自动生成超期预警，纳入 §3.7「异常/超时提醒」。

**E. 角色授权型判定（公告 notice，党政办域）：**
16. 公告不走组织型三级过滤；判定：当前用户角色 ∈ 公告可见角色集合 且 有 M1201 菜单权限 → 可见；否则不展示（列表接口直接过滤，单条查询返回 40304 防枚举）。
17. 公告发布/撤回仅 R-PARTY（党政办）可执行，服务端校验。

### 4.3 越权统一返回码与提示

| 返回码 | 含义 | 用户提示 |
| --- | --- | --- |
| 401 | 未登录/凭证失效 | 请重新登录 |
| 40301 | 无菜单权限 NO_MENU_PERM | 您没有权限访问该功能 |
| 40302 | 无按钮/操作权限 NO_ACTION_PERM | 您没有权限执行此操作 |
| 40303 | 数据范围越权 DATA_SCOPE_DENIED | 数据不存在或您无权访问 |
| 40304 | 记录不存在（防枚举） RESOURCE_NOT_FOUND | 数据不存在或您无权访问 |
| 40901 | 场地已被课表占用 SCHEDULE_CONFLICT | 该时段场地已被课表占用，请另择时段 |
| 40902 | 并发竞争失败（场地被其他预约占用） BOOKING_CONFLICT | 该时段刚被他人预约，请另择时段 |

## 五、边界与特殊场景

1. **跨年级兼课教师**：允许挂靠多个部门，数据范围=GRADE 时取所有挂靠 GRADE 节点并集。
2. **临时借调**：通过调整用户挂靠部门实现，即时生效，不单独建"借调"实体。
3. **代审批 / 代理人**：首版不做（属复杂审批流，已排除）。
4. **审批人数据范围是否覆盖申请单**：是。审批人范围必须 ≥ 申请单归属范围；SELF 无权审批他人申请。
5. **导出是否继承列表页范围**：是。结果集 = 列表页数据范围过滤后结果集，需同时具备导出按钮权限；不接受前端传入任意 ID 列表。
