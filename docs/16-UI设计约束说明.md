## 一、设计约束说明

### 1.1 目标用户（两类视角，信息架构必须分开）

| 视角 | 角色 | 界面形态 | 设计目标 |
| --- | --- | --- | --- |
| **管理视角** | R-PRINCIPAL 校长 | **全校驾驶舱**（大屏） | 汇总优先：登录后首屏即见六域核心指标 + 异常预警；趋势一眼看清、异常一眼看到；少点击、多扫视 |
| 管理视角 | R-VP 校领导 / R-DEAN 教务主任 / R-LOGISTICS / R-MORAL / R-PARTY | **本领域运营大屏** | 同上，但只看本领域 KPI + 本领域异常 |
| 管理视角 | R-GRADE 年级组长 / R-SUBJECT 教研组长 | **本年级 / 本组大屏** | 数据范围由服务端收窄，前端不裁剪 |
| **执行视角** | R-TEACHER 教师 | **个人工作台**（**不是大屏**，docs/14 第一节明确） | 操作路径极短：高频事务 ≤3 步；按钮大、步骤少、别让人想 |
| 执行视角 | R-STUDENT / R-PARENT | **本人 / 本人子女视图** | **不开放大屏**（docs/14 排除项 6） |

**两条硬指标的设计落点（写在界面上，不是写在文档里）：**
- 硬指标①【校长端】：校长首屏 = 异常预警区（置顶） + 六域 KPI 卡（6 个） + 图表区；每个 KPI 卡可点开下钻到业务明细；**任一指标都不需要离开系统去微信/电话追问**（AC-DD2-1 / AC-DD5-1）。
- 硬指标②【教师端】：6 个高频事务全部 ≤3 步，且**步数直接标注在快捷卡与抽屉顶部**（见 §三）。
  > **【用户已裁决】验收口径：正常路径 ≤3 步，异常恢复不计步。** 冲突是外部状态导致（别人先占了时段），不是流程设计缺陷；且设计上已做「提交前用颜色标出冲突（灰=课表占用不可点）」+「一键改约不重填表单」，实际负担很低。
  > **「正常路径」定义**：从**登录后首屏**算起，每 1 次点击或切页 = 1 步，到**提交成功**为止。异常恢复（40901/40902 改约、库存不足改数量）属于失败后的补救路径，**不计入步数**。

### 1.3 色彩与间距硬约束（Token 级，禁止"美观大方"式描述）

**唯一真源**：`design/src/design/tokens.css`（CSS 变量）+ `design/src/design/tokens.ts`（TS 侧，供 ECharts 取值）。业务代码禁止硬编码色值与间距。

| 类别 | Token | 值 | 用途 |
| --- | --- | --- | --- |
| 主色 | `--sa-primary` | `#2B5CE6` | 主行动按钮、链接、选中态 |
| 主色浅底 | `--sa-primary-bg` | `#EEF3FF` | 选中行、主色标签、步数提示条 |

| 预警 | `--sa-warning` | `#B26A00` | 预警指标左边条 / 预警标签 |
| 严重 | `--sa-danger` | `#C0362C` | 超阈值、DANGER 预警、未读角标 |
| 信息 | `--sa-info` | `#4B5563` | 中性信息 |

| 主文本 / 次文本 / 弱文本 | `--sa-text-1/2/3` | `#1B1F27` / `#4E5867` / `#8A94A6` | 标题 / 正文 / 辅助 |

| **图表色板（六域固定）** | `--sa-chart-academic` 教务 `#2B5CE6`<br>`--sa-chart-moral` 德育 `#7A5AF8`<br>`--sa-chart-logistics` 后勤 `#00A38D`<br>`--sa-chart-party` 党政 `#F2A33C`<br>`--sa-chart-science` 科教 `#3E8EDE`<br>`--sa-chart-sport` 体育 `#E8544B` | 同一域在任何图表里必须用同一个色，禁止逐图随机取色 |  |

**色彩使用规则：**
1. 反向指标（排课冲突数、超期审批数等）颜色跟随**好坏**不跟**升降**——冲突数上升是红色，下降是绿色（`KpiCard` 的 `polarity` 字段）。
2. 大屏背景一律 `#F5F7FA`，卡片 `#FFFFFF` + 1px `#E3E8EF` 描边 + 一级阴影。**禁止深色底、禁止发光、禁止渐变主视觉**。
3. 状态表达只用"左边条 3px + 标签"，不用整块深色底（DANGER 卡片例外，用 `#FDECEA` 浅底）。

## 1.5 用户已裁决事项（设计硬约束，开发/验收照此执行）

> 以下三项原为「待用户确认」，现已裁决，从口头约定升为设计硬约束。

### 裁决 1｜步数口径：**正常路径 ≤3 步，异常恢复不计步**
- **口径**：从登录后的首屏起算，每 1 次点击或切页 = 1 步，到提交成功为止；40901/40902 改约、库存不足改数量属**失败恢复**，不计入步数。
- **理由**：冲突由外部状态导致（他人先占时段），不是流程设计缺陷；且设计已做双保险——提交前用颜色标出冲突（灰=课表占用不可点）+ 冲突后一键改约且不重填表单，真实负担很低。
- **落地**：`schemas.ts` 的 `stepText` 维持现状（标注的 2–3 步即正常路径，正确）；`assertSchemaInvariants()` **保持不变、只管正常路径**，不因异常分支报错，也不会因"最坏 4 步"误报（声明上限 3 = 断言上限 3，已确认）。
- **验收**：按 §3.1 AC-UI-1 执行。

### 裁决 2｜大屏刷新时效：**维持 60s 自动刷新，即时推送列 V2.1**
- **首版**：大屏 **60s 自动刷新**（办公查看场景，与 ADR §4.7 Redis 60s 缓存同口径），每个区块显示服务端下发的「数据截止时间」（REQ-DD7）。
- **不做**：不做 WebSocket 实时流、不做 7×24 常驻视觉。
- **V2.1**：异常即时推送（WebSocket）按 docs/14 未来版本扩展方向保留，首版不实现。

### 裁决 3｜教师快捷卡：**维持当前 6 个，不增不配**
- **首版 6 张卡**：物资领用 / 报修 / 请假 / 调课·代课 / 会议室预约 / 实验预约（按使用频次排序，不按菜单顺序）。
- **扩展方式**（后续若要加）：只需在 `design/src/components/QuickApply/schemas.ts` **加一条 Schema**（字段 ≤5、带默认值、写清 `stepText`），再到 `TEACHER_QUICK_ACTIONS` 里加一项；**不动架构、不动组件、不改 Drawer**。

### 2.2 关键设计决策（两个关键页面）

#### 决策 1｜校长驾驶舱：异常置顶，指标其次

```
┌ 页头：全校驾驶舱 · 数据范围全校 · 口径当前学期 | [学期|自然月] ℹ | 数据截止 10:40 · 60s 后刷新 | 刷新 ┐
├ 异常预警（置顶，浅红底卡片）：6 条「严重/预警 + 标题 + 责任人 + 超期时长 + 去处理 →」        ┤
├ KPI 卡 ×6：课表完整率 / 请假人次 / 采购执行率 / 库存告警 / 公告已读率 / 体测达标率              ┤
│            每卡 = 标签 → 32px 数值 → 环比▲/同比；超阈值 = 红色左边条 + 「超阈值」标签 + 浅红底   │
└ 图表区：趋势折线 ×2（采购金额 / 报修量与响应时长）· 分布柱状（各年级请假）· 对比条形（达标率）· 达标雷达（六域健康度）
```

- 为什么异常置顶：硬指标①是"不用去追问"，追问的对象恰恰是异常项；异常在首屏第一屏可见，指标在下。
- 为什么 KPI 卡带环比同比：docs/04 §1.8 定义**同比 = 去年同学期、环比 = 上一学期**，卡片直接显示，不再让人去报表里比。
- 为什么每个指标可下钻：`drillTo` 由服务端下发，越权下钻服务端仍返 40303/40304，前端不预筛（REQ-DD6）。
- 为什么不每个指标都实时：办公查看场景，**60s 自动刷新**（用户已裁决维持此值，即时推送列 V2.1 WebSocket，见 §1.5 裁决 2）。
- 为什么不用深色：办公查看场景（不是走廊挂墙），校长是在办公桌前读数字，深色大屏在白天办公环境反而刺眼且打印/截图不可用。

#### 决策 2｜教师高频事务：快捷卡 + 抽屉一屏表单（不是跳页面 + 分步）

```
工作台首屏 6 张卡（大按钮，104px 高，带图标 + 「2 步」标注）
   ↓ 第 1 步：点卡片（原地展开右侧抽屉，不跳页、不丢上下文）
抽屉内一屏表单（字段 ≤5，带默认值：当前周次 / 常用物资 / 最近空闲时段）
   ↓ 第 2 步：点「提交」
提交成功：直接给单号 + 后续路径（"审批结果将发到消息中心"）
```

- 为什么是抽屉不是新页面：教师是"想到就办"，跳页面 = 多一次等待 + 丢失上下文。
- 为什么默认选中最近空闲时段：把场地类事务从 3 步压回 2 步（上限仍 ≤3）。
- 为什么把步数写在卡片上：硬指标②是要被验收的，写在界面上让教师与验收人都不用猜。
- 无库存物资的「领用」按钮直接禁用 —— 不制造必然失败的路径（同时也不是权限实现，服务端仍校验）。

#### 决策 3｜冲突的用户侧反馈（40901 / 40902 / 库存不足 / 名额已满）

`ConflictAlert` 组件强制三段式：

| 错误码 | 标题（发生了什么） | 为什么 | 怎么办 |
| --- | --- | --- | --- |
| **40901** 课表占用 | 该时段已被课表占用，无法预约 | 排课是场地占用的权威来源：{场地} {时段}（{占用来源}），预约不能覆盖排课 | 可改约空闲时段 chips（一键重提）+「查看该场地课表」（仅在拿到占用明细时给，见下） |
| **40902** 并发竞争 | 该时段刚被他人预约 | {场地} {时段} 在你提交的同时被其他老师预约成功，同一时段只能有一个预约 | 可改约空闲时段 chips +「重新选择时段」 |
| **40903** 库存不足 | 库存不足，本次申请未提交 | {物资} 当前可用 3 件，你申请了 8 件（C9 原子扣减失败，AC-B1-3 不超卖） | 「改为申请 3 件」一键重提 |
| **40904** 名额已满 | 名额已满，本次报名未成功 | {活动} 名额 40 人，已全部报满 | 「查看其它场次」 |

**【越权红线 · 架构裁决，设计必须遵守】** `occupiedBy`（占用来源：班级 + 学科 + 教师）是**课表数据**，按 docs/03 矩阵课表对 R-TEACHER 只有「本人/本班」范围。若 SELF 范围教师预约实验室时回传他人班级与教师姓名，等于借冲突提示反查他人课表。因此：

- 请求人范围覆盖该占用（ALL，或 GRADE 且命中该年级/班级）→ 下发「班级 + 学科 + 教师」；
- 否则服务端只下发占位文案「已被课表占用」——`ConflictAlert` 必须**兼容 `occupiedBy` 缺失/降级**，兜底成占位文案，禁止渲染 undefined；
- 是否给「查看该场地课表」入口由服务端下发的布尔 `conflict.hasOccupancyDetail` 决定（**不用字符串比较判断**——占位文案会随字典与文案微调变化，字符串比较迟早失效）；
- 该入口的最终可见性 = `hasOccupancyDetail`（服务端管数据范围）**∩** M0703 菜单权限（前端管入口，用动态路由表判断），两者取交集——不把用户引到必然 403 的页面（反模式 A4）；
- `SpaceBooking` 的占用矩阵**只承载状态、不承载占用人身份**：格子没有 text 字段，tooltip 只用固定状态文案（FREE / SCHEDULE / RESERVED），RESERVED 对 SELF 用户只见状态不见人；
- `suggestions` 只会来自「请求人可预约范围内且当前 FREE」的格子并已过数据范围过滤，前端可直接渲染为可点击按钮。

另外在**提交前**就把冲突显示出来：`SpaceBooking` 的占用矩阵用颜色区分「被课表占用（灰，不可点）/ 已被预约（浅蓝，不可点）/ 空闲（白，可点）」，让用户在第 2 步就看得见，而不是提交后才被拒。

#### 决策 4｜分角色视图：前端不写角色分支

```
GET /api/dashboard/overview?dim=TERM → { roleCode, templateKey, kpis[], charts[], alerts[], scopeText, dataAsOf }
   → TEMPLATES[templateKey]   // 只取「布局描述」：栅格宽 / 高度 / 顺序
   → 渲染
```
`views/dashboard/bigscreen/templates.ts` 里**只有布局，没有口径、没有过滤条件**。所以"年级组长只看到本年级"是服务端实现，不是前端裁剪（AC-DD5-1）。新增角色 = 服务端加一个 `templateKey` + 模板表加一行，不动页面代码。

**权限主路径**：本页只对**有 M15 菜单权限**的角色注册路由并渲染。教师 / 学生 / 家长在 docs/03 的 M15 矩阵是「—」（无菜单），服务端对他们的 `overview` 请求直接返回 **40301**，前端也不渲染入口。`templateKey = NONE` **不是**"无大屏角色也能调 overview"的依据，它只服务于「有 M15 菜单但没有预置模板」的自建角色（`R-CUSTOM-*`），让他们看到空态而不是报错。

#### 决策 5｜消息中心：不做正文预览

铃铛 → 抽屉 → 只有「分类 tag + 未读点 + 时间 + 标题」，点击直接跳业务详情页（如公告跳 M1201），已读回执由业务端记录。抽屉顶部常驻一条说明，避免用户把"角标清零"误认为"业务已读"。查看最新消息 = 登录 → 点铃铛 = **2 步**（AC-MS6-1）。

## 三、高频事务操作路径（步数）

**步数口径**：从进入系统（登录后的首屏）到提交成功，每 1 次点击 / 切页 = 1 步。

| # | 高频事务 | 操作路径 | 步数 | 界面落点 |
| --- | --- | --- | --- | --- |
| 1 | **物资领用申请** | ①工作台点「物资领用申请」卡 → ②抽屉内确认物资/数量/用途，点「提交」 | **2 步** ✅ | `workbench` 快捷卡 / `material/apply` 物资卡「领用」；抽屉顶标注「2 步」 |
| 2 | **报修提交** | ①点「报修提交」卡 → ②填位置/类型/描述，点「提交」 | **2 步** ✅ | `workbench` / `repair/submit` |
| 3 | **请假申请** | ①点「请假申请」卡 → ②填类型/天数/事由，点「提交」 | **2 步** ✅ | `workbench` / `leave/apply` |
| 4 | **调课 / 代课申请** | ①点「调课/代课」卡 → ②填原因/节次/说明，点「提交」 | **2 步** ✅ | `workbench` / `schedule-change/apply` |
| 5 | **会议室预约** | ①点「会议室预约」卡 → ②抽屉默认已选中最近空闲时段（要换则点一下）→ ③点「提交」 | **2–3 步** ✅ | `workbench` / `party/meeting-room`（从场地格子进入则 ①点格子 ②提交 = 2 步） |
| 6 | **实验预约** | ①点「实验预约」卡 → ②选/确认时段 → ③点「提交」 | **2–3 步** ✅ | `workbench` / `science/lab` |
| — | 查看最新消息（对照） | ①登录后点顶部铃铛 → 见未读列表 | **2 步** ✅ | `MessageBell`（AC-MS6-1） |
| — | 打开本角色大屏（对照） | ①登录后首屏即本角色大屏（或工作台一键进入） | **≤2 步** ✅ | `bigscreen`（AC-DD2-2） |

**步数口径（用户已裁决，验收按此执行）**：
- **正常路径 ≤3 步**；**异常恢复（改约 / 改数量）不计步**。理由：冲突由外部状态导致（他人先占），非流程设计缺陷；且设计上已双保险——①提交前用颜色标出冲突（灰=课表占用不可点、浅蓝=已预约），②冲突后用 `ConflictAlert` 一键改约且不重填表单。
- 「正常路径」定义：从**登录后首屏**起算，每 1 次点击或切页 = 1 步，到**提交成功**为止。
- 上表 6 个事务按正常路径计：2 步 ×4 + 2–3 步 ×2，**全部 ≤3 步** ✅。会议室/实验预约从场地格子进入时为 2 步。
- **步数是怎么压下来的（设计手段）**：①快捷卡一步进入（不翻菜单）；②抽屉原地展开（不跳页）；③当前周次 / 常用物资 / 最近空闲时段全部带默认值；④字段 ≤5 个、一屏填完；⑤提交即给单号与后续路径。
- **自动守卫**：`schemas.ts` 的 `assertSchemaInvariants()` 只校验**正常路径**的声明步数（≤3）与字段数（≤5），**不因异常分支报错**——因此「最坏情况 4 步」不会触发误报（已确认：声明上限最大为 3，断言上限为 3，不放宽也不收紧）。

### 3.1 设计侧可测试验收标准（建议挂到门禁6 执行）

前置说明：步数不是"写在文档里就算数"——`QuickApply/schemas.ts` 内置**运行时不变量断言**（`assertSchemaInvariants()`，开发期自动执行）：改字段不同步 `stepText`、字段超过 5 个、声明步数超过 3 步，刷新页面直接抛错，不让它悄悄溜到验收。

| 编号 | 验收标准 | 验证方式 |
| --- | --- | --- |
| **AC-UI-1** | 任一高频事务**界面上声明的步数** ≤3，且与**实测点击次数**一致 | 逐个事务从登录后首屏开始点，记录点击数，与卡片/抽屉顶部 `stepText` 比对。**验收口径（用户已裁决）：正常路径 ≤3 步；异常恢复（改约 / 改数量）不计步** |
| **AC-UI-2** | 每个高频事务表单字段 ≤5（一屏填完，无分步向导） | `assertSchemaInvariants()` 断言 + 目测 |
| **AC-UI-3** | 所有趋势图/报表**默认学期口径**；切换自然月后可见数据集合与越权判定不变 | 登录后不点切换器直接看默认值；切 MONTH 后比对可见记录集合 |
| **AC-UI-4** | 大屏指标与下钻明细**不含**平台级配置对象（字典 / 流程模板 / 菜单 / 角色 / 部门） | 以非 R-ADMIN 角色请求 overview + drill，检查返回体 |
| **AC-UI-5** | 大屏模板表**不含任何 `if (role === ...)` 分支** | grep `templates.ts`（架构已升为 ADR §4.7 红线） |
| **AC-UI-6** | 冲突/并发/库存/名额失败返回 40901–40904 三段式反馈，**不出现**通用「操作失败」 | 触发各场景，检查是否给出「发生了什么 + 为什么 + 怎么办」 |
| **AC-UI-7** | 冲突提示对越权数据脱敏：范围不够时 `occupiedBy` 为占位文案、`hasOccupancyDetail=false` 且无课表入口 | 以 SELF 范围教师触发 40901，检查返回体与界面 |
| **AC-UI-8** | 同域图表跨图同色（六域色板），趋势图无平滑曲线 | 目测 + 检查 `colorKey` 取值 |
