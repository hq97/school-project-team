# 中学校务数字化平台 · 消息中心与通知 PRD（跨域基础模块）

> 阶段：Phase 1 需求（跨域基础模块，与 docs/07 可配置审批流并列）| 产出人：教育产品专家（许清楚）| 门禁：门禁 1（需求门禁）
> 定位：六域所有「通知」统一走消息中心（审批结果 / 公告推送 / 会议通知 / 家长确认提醒 / 销假提醒 / 超期预警等），消除各域各自实现通知的重复与割裂。
> 复用：RBAC（docs/03）、数据权限（docs/04，返回码 401/40301/40302/40303/40304）。

---

## 一、目标用户与场景

### 全体用户（接收视角）——要收得到、看得清、不遗漏
1. **消息列表**：统一收件箱，按分类（审批/公告/会议/预警/系统）查看。
2. **已读/未读**：未读角标，单条已读、批量已读。
3. **订阅设置**：可订阅/退订某类消息。

### 管理员（配置视角）——要可配、可管理
1. **消息模板管理**：配置消息模板（标题/正文占位符）。
2. **触发规则管理**：配置哪些业务事件触发哪类消息、发给谁。

### 处室/校长（管理视角）——要触达、要回执
1. **公告/会议/审批通知触达**：通过消息中心统一发送并送达；用户点击后跳转业务端，**由业务端统计已读回执**（消息中心不独立维护业务对象的已读状态，口径见 AC-MS8-1 与排除项 2）。

> 注（已读统一口径）：六域业务对象（公告 / 审批单 / 请假单 / 会议通知等）的已读回执由**各业务端**统计；消息中心**只维护站内信自身的已读 / 未读**用于未读角标，**不独立维护业务对象的已读状态**。同一业务对象的已读**只有一个口径——以业务端为准**（见 AC-MS8-1、排除项 2、docs/04 §3.10、docs/09 REQ-L2）。

## 二、需求清单（REQ-MS，标 P0/P1）

- **REQ-MS1｜统一消息列表**：统一站内信收件箱，按分类（审批/公告/会议/预警/系统）筛选，分页。目标用户：全体。P0。
- **REQ-MS2｜已读/未读管理**：未读角标（铃铛/工作台入口）、单条已读、批量已读、未读列表。目标用户：全体。P0。
- **REQ-MS3｜消息订阅设置**：用户按消息类型订阅/退订（如超期预警、审批通知），默认全订阅。目标用户：全体。P1。
- **REQ-MS4｜消息模板管理**：管理员配置消息模板（标题/正文 + 占位符如 {申请人}{事由}{结论}），**模板须按业务类型区分命名**——同类动作落在不同业务域时须建为**独立模板**（如「请假家长确认」docs/08 REQ-I2 与「违纪家长确认」docs/08 REQ-J2 是两个独立模板，不得复用同一模板），避免开发阶段因模板复用造成语义混淆与推送串味。目标用户：系统管理员。P0。
- **REQ-MS5｜触发规则**：统一触发规则——审批通过/驳回、公告发布、会议通知、家长确认提醒、销假提醒、超期预警（请假未销假/资产未归还/审批滞留）等业务事件，自动生成消息并送达相关人。目标用户：开发（与各域联动）。P0。
- **REQ-MS6｜消息中心入口**：工作台顶部铃铛/消息入口，未读数字角标，点击进入消息列表（≤2 步）。目标用户：全体。P0。

## 三、验收标准（含两条硬指标）

**两条硬指标：**
- 硬指标①【校长端】：任一核心指标无需离开系统追问——消息触达是其辅助（预警/审批结果通过消息中心送达，校长不离开系统即知）。
- 硬指标②【高频事务 ≤2 步】：用户查看最新消息 ≤2 步（登录→点击铃铛即见未读）。

**逐条可测试验收标准：**
- AC-MS1-1：六域通知（审批/公告/会议/家长确认/销假/超期）均落入统一消息列表，按分类可筛选。
- AC-MS2-1：未读角标数字准确，单条/批量已读后角标实时减少。
- AC-MS3-1：用户退订某类消息后不再收到该类消息，订阅后恢复。
- AC-MS4-1：管理员配置消息模板，业务触发时按模板渲染标题/正文。
- AC-MS5-1：审批通过/驳回、公告发布、会议通知、家长确认、超期预警等六域业务事件触发后，相关人在消息中心收到对应消息——校长 / 处室在系统内即知事件结果与异常，**无需离开系统去微信或电话追问**。✅硬指标①
- AC-MS6-1：用户查看最新消息 ≤2 步（登录→点击铃铛）。✅硬指标②
- AC-MS7-1：消息中心数据范围随接收人过滤——用户只能看到发给自己（或自己可见角色）的消息，越权访问他人消息服务端拒绝（40303/40304）。
- **AC-MS8-1【已读统一口径】**：用户从消息中心点击某业务消息跳转到业务对象（公告 / 审批单 / 请假单 / 会议通知等）时，**由业务端记录已读回执**；消息中心仅维护「站内信自身的已读/未读」用于未读角标，**不独立维护业务对象的已读状态**。同一业务对象的已读**只有一个口径——以业务端为准**（见 docs/04 §3.10、docs/09 REQ-L2）。

> 注（硬指标挂点）：硬指标①落点为 **AC-MS5-1**（六域业务事件通过消息中心统一触达，校长 / 处室不离开系统即知）；硬指标②落点为 **AC-MS6-1**（查看最新消息 ≤2 步）。
> 注（口径一致性）：本模块**任何位置**不再出现"消息中心统计已读回执 / 支持已读回执统计"的表述——已读回执一律归业务端，见本节 AC-MS8-1 与第四节排除项 2。

## 四、明确排除项（本次不做什么）

1. 不含短信/微信/邮件等外部消息推送（首版仅站内信；家校通外部推送列未来版本，对齐德育域 V2.0）。
2. 不含消息撤回/定时发送/消息已读回执的强制闭环（公告已读回执由党政办域单独实现，消息中心只负责送达）。
3. 不含聊天/即时通讯（IM）能力（消息中心是通知，不是聊天）。
4. 不含手机原生 App 推送（沿用 Web 响应式 + 站内信）。

## 五、未来版本扩展方向 + 权限数据范围表

### 未来版本扩展方向
- **V2.0（外部推送）**：短信/微信/邮件推送，家长确认提醒外发。
- **V2.1（消息增强）**：消息定时发送、撤回、已读回执强制闭环、消息聚合摘要。
- **V2.2（IM 轻协作）**：站内轻量沟通（非通知类）。

## 对下游的输入提示

- **菜单**：消息中心入口挂 M01 工作台下（建议 M0105「消息中心」，顶部铃铛），管理员消息模板/触发规则挂 M05 系统管理下（M0506 消息模板）。
- **设计（交互约束，必守）**：①**业务类消息（公告 / 审批单 / 请假单 / 会议通知等）一律不做站内正文预览**——点击消息**直接跳转到对应业务对象详情页**（如公告跳 M1201），由业务端记录已读回执；若做成站内预览并就地标记站内信已读，会产生「角标消失但业务对象仍显示未读」的感知落差，与「已读唯一口径（AC-MS8-1）」直接冲突。②**未读角标仅反映「站内信自身」的已读/未读状态，不代表业务对象的已读状态**——角标清零 ≠ 业务已读回执完成；设计稿、文案与 AC 说明均不得将两者混为一谈。
- **开发**：消息中心为独立服务/模块，各域业务事件通过统一消息接口（发布事件 → 消息中心按模板渲染 → 写入接收人收件箱）；接收人由各域业务逻辑计算（审批人/可见角色/家长/班主任等），服务端校验数据范围。
- **测试**：重点验「六域通知统一收敛到消息中心」+「越权访问他人消息被拒」+「未读角标准确」。
