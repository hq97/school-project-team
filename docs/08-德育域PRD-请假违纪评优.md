## 〇、本域关键结论（先读）

1. **「本班」粒度 → 不新增第四级权限级别，映射到现有「本年级」级别 + 部门树新增「班级(CLASS)」组织载体。**（详见 §五 与「数据权限粒度结论」）
2. **家长数据范围 → 关系型归属**：通过 `student_parent`（家长-学生多对多）落到「本人子女」最小单元，区别于现有的组织型归属（部门树）。
3. **审批一律复用 REQ-D3 可配置审批流**：学生请假、违纪处理、评优审批的审批人一律表述为「由流程模板配置的审批角色审批」，不写死具体岗位。
4. **RBAC 沿用**：菜单/按钮权限沿用 vue-pure-admin（docs/03），德育域新增菜单挂 M09/M10/M11；学生(R-STUDENT)、家长(R-PARENT) 补充进角色矩阵。
5. **三级权限**：服务端逐接口校验，沿用 docs/04 返回码约定（401/40301/40302/40303/40304）。

## 一、目标用户与场景（校长 / 德育处 / 班主任 / 学生 / 家长）

### 校长（管理视角）——要汇总、要趋势、要异常
1. **请假统计**：全校请假时长/类型/频次分布、异常集中时段。
2. **违纪统计**：违纪类型/处分等级/年级分布趋势。
3. **评优结果**：各评选项目获奖名单、班级覆盖率、结果归档。

### 德育处（管理/执行视角）——要全、要规范、要留痕
1. **违纪登记与处理**：登记全校违纪、按流程处理（谈话/警告/处分）、追踪处理结果。
2. **评优标准维护与审批**：维护评选标准、审核推优、公示、归档。
3. **全校统计**：请假/违纪/评优汇总。

### 班主任（执行/管理视角）——要管得动本班
1. **本班学生请假**：代学生发起请假、销假，看本班请假情况。
2. **本班违纪登记**：登记本班违纪、跟进处理。
3. **班级推优申报**：按标准提交本班推优名单。

### 学生（执行视角）——要能自助、要少填表
1. **请假申请**：选类型→填时长/原因→提交，≤3 步。
2. **查看本人记录**：本人请假/违纪/评优记录。

### 家长（知情/确认视角）——要能确认、能知情
1. **请假确认**：对子女请假申请确认（同意/拒绝），≤3 步。
2. **查看子女记录**：本人子女的请假/违纪记录（仅本人子女）。

## 二、需求清单（REQ-I / J / K，标 P0/P1）

### I. 学生请假（请假/销假）
- **REQ-I1｜请假申请**：学生或班主任发起请假，含请假类型（事假/病假/其他）、时长（起止时间/天数）、原因、附件（病假证明可传）。目标用户：学生/班主任。P0。
- **REQ-I2｜家长确认**：学生发起的请假，须经关联家长在系统内确认（同意/拒绝），作为审批前置环节。目标用户：家长。P0。
- **REQ-I3｜请假审批**：由**流程模板配置的审批角色**审批（可配 1 级或多级）。目标用户：审批角色成员。P0。
- **REQ-I4｜销假闭环**：请假到期后由学生/班主任发起销假，记录实际返校时间，流程关闭。目标用户：学生/班主任。P0。
- **REQ-I6｜请假超期预警**【补写 C10】：请假到期未销假，系统自动生成超期预警（纳入 docs/04 §3.7 异常/超时提醒），推送班主任/德育处。目标用户：班主任/德育处。P1。
- **REQ-I5｜请假统计**：校长/德育处查看请假时长/类型/频次/年级分布。目标用户：校长+德育处。P1。

### J. 违纪登记与处理
- **REQ-J1｜违纪登记**：班主任/任课教师/德育处登记违纪（学生、时间、地点、违纪类型、描述、证据）。目标用户：班主任/任课教师/德育处。P0。
- **REQ-J2｜违纪处理流程**：按流程处理（谈话/警告/严重警告/记过/留校察看等处分等级），由**流程模板配置的处理角色**逐级处理。**严重处分家长确认**：当处分等级为「记过 / 留校察看」等**严重级**时，须经关联家长在系统内确认（知悉/同意）后方可结案，否则流程挂起（与 REQ-I2「请假家长确认」相互独立，本条为本域**违纪专用**确认环节）。目标用户：处理角色成员 + 家长。P0。
- **REQ-J3｜处理结果追踪**：状态（登记→处理中→已处理→已撤销）、处分等级、处理意见、处理人全程留痕。目标用户：德育处/班主任。P0。
- **REQ-J4｜违纪查询**：学生看本人、家长看本人子女、班主任看本班。目标用户：学生/家长/班主任。P0。
  - **家长可见边界【B4】**：家长仅可见「违纪事实 + 通知」，**不含内部处理意见/谈话记录**；严重处分级（记过/留校察看）需家长确认（服务端按家长视角字段过滤，见 docs/04 §4.1）。
- **REQ-J5｜违纪统计**：校长/德育处看违纪类型/等级/年级分布趋势。目标用户：校长+德育处。P1。
- **REQ-J6｜家长未确认催办与超时强制结案**【补写 C10】：严重处分（记过/留校察看）家长确认设**可配超时阈值**（默认 3 天）；超期自动生成**催办提醒**并走消息中心推送家长（对齐 docs/04 §3.7 超期类型「家长未确认超期」）；**超期且经 N 次催办（N 可配，默认 2 次）仍无确认的，德育处可「强制结案」**——须填写强制结案原因并记录操作人、时间，全程留痕，避免流程无限挂起。**配置载体**：超时阈值与催办次数 N 配置在**德育字典**（与处分等级字典同处），**不新增配置机制**。目标用户：德育处 + 家长。P1。

### K. 评优评先
- **REQ-K1｜评选标准维护**：德育处维护评选项目（三好学生/优秀班干部等）、评选标准、名额、周期。目标用户：德育处。P0。
- **REQ-K2｜班级推优/申报**：班主任按标准提交本班推优名单/申报材料。目标用户：班主任。P0。
- **REQ-K3｜评优审批**：由**流程模板配置的审批角色**审批（班级推优→年级/德育处审批→校级审定，多级可配）。目标用户：审批角色成员。P0。
- **REQ-K4｜公示**：审批通过后进入公示期（时长可配），公示期内可异议。目标用户：德育处。P0。
- **REQ-K5｜结果归档**：公示无异议后结果归档，生成获奖名单，可查询。目标用户：德育处。P0。
- **REQ-K6｜评优统计**：校长/德育处看评优结果统计。目标用户：校长+德育处。P1。

## 三、验收标准（含两条硬指标）

**两条硬指标（需求门禁，缺失即阻断）：**
- 硬指标①【校长端】：任一核心德育指标（请假统计 / 违纪统计 / 评优结果）无需离开系统去微信或电话追问。
- 硬指标②【高频事务 ≤3 步】：教师端 + **学生端/家长端**高频事务均 ≤3 步（学生请假申请、家长请假确认、班主任违纪登记、班主任班级推优）。

### 请假
- AC-I1-1：学生提交请假申请（选类型→填时长/原因→提交）≤3 步。✅硬指标②（学生端）
- AC-I1-2：请假单必填类型与时长，病假可传附件证明。
- AC-I2-1：学生发起的请假，未获关联家长确认前不得进入审批环节（家长确认是前置）。
- AC-I2-2：家长对子女请假确认（同意/拒绝）≤3 步。✅硬指标②（家长端）
- AC-I3-1：请假审批由流程模板配置的审批角色执行，审批人数据范围必须覆盖请假学生归属（越权审批服务端拒绝）。
- AC-I4-1：请假到期后可销假，记录实际返校时间，流程关闭留痕。
- AC-I5-1：校长查看请假时长/类型/频次/年级分布，无需问德育处。✅硬指标①

### 违纪
- AC-J1-1：班主任/任课教师/德育处登记违纪（选学生→填类型/描述→提交）≤3 步。✅硬指标②（教师端）
- AC-J1-2：违纪记录含学生、时间、地点、类型、描述、证据（可传附件）。
- AC-J2-1：违纪处理按流程模板配置的处理角色逐级流转，处分等级（谈话/警告/严重警告/记过/留校察看）可配置。
- **AC-J2-2**：处分等级为「记过 / 留校察看」等严重级时，**未经关联家长在系统内确认不得结案**，流程挂起并推送提醒；家长在违纪查询列表确认（知悉/同意）≤3 步（按钮见 docs/03 BTN-DISC-PARENT-CONFIRM，消息触达见 docs/15 REQ-MS5，对齐 docs/04 §4.1 B4）。✅硬指标②（家长端）
- AC-J3-1：违纪状态全程留痕（登记/处理中/已处理/已撤销），处理人与处理意见可查。
- AC-J4-1：学生仅看本人违纪、家长仅看本人子女违纪、班主任仅看本班违纪，越权查询服务端拒绝（40303/40304）。
- AC-J5-1：校长查看违纪类型/等级/年级分布趋势，无需问德育处。✅硬指标①
- **AC-J6-1**：严重处分（记过/留校察看）在超时阈值内未获家长确认，系统自动生成催办提醒并推送家长，累计达 N 次后仍无确认的，德育处可执行强制结案。
- **AC-J6-2**：强制结案须填写原因并留痕（原因 + 操作人 + 时间 + 此前催办次数），且业务上**仅德育处（R-MORAL）可执行**——教师、家长、学生均无此权限（按钮见 docs/03 BTN-DISC-FORCE-CLOSE，越权服务端拒绝 40301/40302）。**R-ADMIN 澄清**：R-ADMIN 作为平台超管按 RBAC 基线持有全权限（见 docs/03 角色清单），与「业务语义上限德育处执行」二者不冲突——超管权限属平台运维兜底，不改变业务执行角色约定。
- **AC-J6-3**：强制结案后流程从挂起态转为已结案，违纪状态与家长可见范围同步更新（对齐 docs/04 §4.1 B4 家长仅见违纪事实+通知）。

### 评优
- AC-K1-1：德育处维护评选项目/标准/名额/周期，保存即时生效。
- AC-K2-1：班主任提交本班推优名单 ≤3 步（选项目→选学生→提交）。✅硬指标②（教师端）
- AC-K2-2【补写 C9】：评优名额并发不超订——多名额并发提交时，名额扣减原子唯一，超额提交被拒。
- AC-K3-1：评优审批由流程模板配置的审批角色逐级审批（推优→年级/德育处→校级审定可配）。
- AC-K4-1：审批通过后进入公示期（时长可配），公示期内可异议，公示记录留痕。
- AC-K5-1：公示无异议后结果归档，生成获奖名单，可查询。
- AC-K6-1：校长查看评优结果统计，无需问德育处。✅硬指标①

## 四、明确排除项（本次不做什么）

1. 不含家校通消息推送（短信/微信推送家长确认）——首版家长确认仅站内通知。
2. 不含学生/家长手机原生 App（沿用 Web 响应式 H5）。

7. 不含学生综合素质评价（综评）全套（超出本域）。

## 附：数据权限粒度结论与家长口径（已确认，已落地 docs/03/docs/04）

### 一、「本班」粒度结论：不新增第四级权限级别（已确认）

**结论**：德育域的「本班」**不新增独立的第四级数据权限级别**，而是映射到现有「本年级」级别 + 部门树新增「班级(CLASS)」组织载体。

**理由**：
1. docs/04 已用「本组（教研组）」作为「本年级层级下的组织载体细分」先例，班级完全同构——只需在部门树新增 `deptType=CLASS`，挂 `GRADE` 节点下。
2. 数据范围「级别」（角色属性 SELF/GRADE/ALL）保持三级不变，避免权限矩阵、RBAC、服务端校验算法全面膨胀。
3. 「班主任看本班」= 数据范围级别「本年级」+ 组织载体收窄到「本班班级节点」，判定算法复用 docs/04 §4.2 的"沿部门树找节点"逻辑，仅把载体从 GRADE 细化到 CLASS。
4. 德育处看全校 = ALL，无需改动。

**落地（已修订 docs/04）：**
- docs/04 §1.2 部门树类型表已新增 `CLASS`（班级），挂 `GRADE` 节点下。
- 班主任角色数据范围=「本年级」，通过 `head_teacher.classId` 绑定其担任班主任的班级，实际可见范围收窄到该 CLASS 节点。
- docs/04 §1.3/§4.2 判定算法已补充「本班」载体判定。

### 二、家长「本人子女」归属口径（关系型归属）

- 家长与学生为**多对多**关系，建 `student_parent(studentId, parentUserId)` 关联表。
- 家长角色数据范围 = SELF 的**关系型扩展**：仅能访问「其关联子女」的记录，不是通过部门树判定。
- 判定：家长查询某学生记录时，先校验 `student_parent` 是否存在 `(parentUserId=当前家长, studentId=目标学生)`，存在才放行；否则 40304（防枚举）。
- 一个家长多子女时，其可见范围 = 全部关联子女记录的**并集**。
- 学生本人数据范围 = SELF，判定 `studentId == 当前学生用户ID`。

> 服务端校验规则在 docs/04 §4 基础上新增一类「关系型归属」判定（家长-子女），与「组织型归属」（部门树）并存。
