## 一、目标用户与场景（校长 / 科教负责人 / 教师 / 学生）

### 校长（管理视角）——要产出、要成果、要趋势
1. **科教资源看板**：资源总数、下载量、学科分布。
2. **竞赛成果**：竞赛项目数、报名数、获奖数。
3. **课题进展**：立项数、在研数、结题数、超期课题。

### 科教负责人（执行/管理视角）——要组织、要评审、要归档

> **业务称谓，非独立角色**：「科教负责人」为岗位职责称谓，由 **R-SUBJECT（教研组长）+ R-TEACHER + 流程模板配置的审批/评审角色**承担，**不新增 R-SCIENCE**（见本文档 §已确认决策1；docs/03 角色清单中无 R-SCIENCE）。

1. **资源库管理**：资源审核、分类维护。
2. **实验预约管理**：实验室/器材预约审批、冲突处理。
3. **竞赛与课题组织**：竞赛发布、报名汇总、评审；课题立项/结题审批。

### 教师（执行视角）——要少跑腿、要共享
1. **上传/检索资源**：≤3 步上传，分类检索下载。
2. **实验预约 / 竞赛报名 / 课题申报**：≤3 步提交。

### 学生（参与视角）——要能参赛、能查
1. **竞赛报名/查看结果**：本人报名与获奖查询。

## 二、需求清单（REQ-M，标 P0/P1）

### M. 科学教育
- **REQ-M1｜科教资源上传**：教师上传资源（标题/学科/类型/文件/简介/标签），提交审核。目标用户：教师。P0。
- **REQ-M2｜资源分类检索**：按学科/类型/标签/关键词检索，列表+详情。目标用户：全体。P0。
  - **资源可见分级【补写 E4】**：资源可见范围分级（公开/全校/本组），上传时选择；检索下载按资源可见范围 + 用户角色过滤（与公告角色授权型/组织型思路一致）。
- **REQ-M3｜资源下载**：有权限用户下载资源，记录下载量。目标用户：全体。P0。
- **REQ-M4｜实验预约**：教师预约实验室/器材——**实验室取自统一场地对象 space**（`spaceType=LAB`，见 docs/04 §1.11），**实验器材取自统一资产台账 asset**（`assetType=实验器材`，见 docs/04 §3.9）；提交时**须先读取该「实验室 + 时段」的课表占用做冲突校验**（命中则拒绝，见 docs/04 §1.12），合格后再按并发规则竞争同一时段与库存。冲突即时拦截，复用场地/物资预约模板。目标用户：教师。P0。
- **REQ-M5｜实验预约审批**：由**流程模板配置的审批角色**审批预约，通过后锁定时段。目标用户：审批角色成员。P0。
- **REQ-M6｜竞赛项目发布**：科教负责人发布竞赛（名称/类别/报名时间/评审规则/名额）。目标用户：科教负责人。P0。
- **REQ-M7｜竞赛报名**：教师/学生提交报名（选项目→填材料→提交），≤3 步。目标用户：教师/学生。P0。
- **REQ-M8｜竞赛评审与结果公示**：由**流程模板配置的评审角色**评审，结果公示与归档，复用评优审批思路。目标用户：评审角色成员。P0。
- **REQ-M9｜课题申报**：教师提交课题申报（选题/论证/成员/周期）。目标用户：教师。P0。
- **REQ-M10｜课题立项审批**：由**流程模板配置的审批角色**立项审批。目标用户：审批角色成员。P0。
- **REQ-M11｜课题过程材料**：在研课题上传过程材料（开题/中期/阶段成果），留痕。目标用户：教师。P1。
- **REQ-M12｜课题结题**：提交结题材料，由**流程模板配置的审批角色**结题审批，归档。目标用户：教师。P0。

## 三、验收标准（含两条硬指标）

**两条硬指标：**
- 硬指标①【校长端】：任一核心科教指标（资源下载量 / 竞赛获奖数 / 课题立项与结题数 / 超期课题）无需离开系统去微信或电话追问。
- 硬指标②【高频事务 ≤3 步】：教师上传资源、实验预约、竞赛报名、课题申报 ≤3 步。

**逐条可测试验收标准：**
- AC-M1-1：教师上传资源（选文件→填标题/学科/类型→提交）≤3 步，提交进入审核。✅硬指标②
- AC-M2-1：资源按学科/类型/标签/关键词检索，结果准确。
- AC-M3-1：有权限用户可下载资源，系统记录下载量，校长查看下载量无需问科教。✅硬指标①
- AC-M4-1：实验预约（选实验室/器材→时段→提交）≤3 步，时段冲突即时拦截。✅硬指标②
- AC-M4-2【补写 C9】：实验室/实验器材时段与库存并发不超订——同时段并发预约仅一人成功，器材库存原子扣减。
- **AC-M4-3【补写 场地占用】**：实验预约提交时（**在并发竞争之前**），服务端先读取该「实验室 + 时段」的**课表占用**（docs/06 已发布课表）做冲突校验——命中课表占用一律**拒绝并返回 40901（场地已被课表占用）**，不进入并发判定。**语义区别于 AC-M4-2**：M4-2 是与「其他预约请求」抢同一时段/同一库存（C9 并发），M4-3 是与「已排定的课表」冲突（排课优先单向校验，见 docs/04 §1.12）。
- AC-M5-1：预约由流程模板配置的审批角色审批，通过后时段锁定、他人不可重复预约。
- AC-M6-1：竞赛发布后，目标用户可见并可在报名期内报名。
- AC-M7-1：竞赛报名（选项目→填材料→提交）≤3 步。✅硬指标②
- AC-M7-2【补写 C9】：竞赛报名名额并发不超订——名额满后并发提交被拒（名额原子扣减）。
- AC-M8-1：竞赛评审由流程模板配置的评审角色执行，结果公示与归档留痕；校长查看获奖数无需问科教。✅硬指标①
- AC-M9-1：课题申报（选题→论证→提交）≤3 步。✅硬指标②
- AC-M10-1：立项审批由流程模板配置的审批角色执行，立项/驳回留痕。
- AC-M11-1：在研课题可上传过程材料，按时间留痕。
- AC-M12-1：结题审批通过后归档，校长查看立项/结题数与超期课题无需问科教。✅硬指标①

## 四、明确排除项（本次不做什么）

1. 不含资源在线预览/在线编辑（仅上传/下载，在线预览留后续）。
2. 不含大型文件断点续传/转码（首版常规上传）。
3. 不含实验安全/危化品台账（超出本域，首版实验预约不涉及危化品管理）。
4. 不含竞赛线上评审打分引擎（首版人工评审，复用评优思路）。
5. 不含课题经费管理（课题仅申报/立项/过程/结题，不含经费报销）。
6. 审批沿用固定线性（REQ-D3），不含会签/或签/条件分支/转签/代理。
7. 不含手机原生 App（沿用 Web 响应式）。

## 已确认决策（2026-10-29，用户拍板）

1. **不新增 R-SCIENCE**：科教域复用 R-SUBJECT（教研组长）+ R-TEACHER + 流程模板配置的审批/评审角色。

4. **实验器材 → 统一资产台账 asset**：实验器材纳入统一「资产台账 asset」（assetType=实验器材），与后勤物资、体育器材共用底层台账，业务场景独立。
