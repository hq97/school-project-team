> **M0505 权限**：菜单**仅 R-ADMIN 可见且可维护**；字典项增删改按钮 **BTN-DICT-EDIT** 仅 R-ADMIN 持有，其它角色一律不授予（含 R-PRINCIPAL）。

### 2.1 角色可扩展性规范

1. **本文档 12 个角色是「出厂预置基线」，不是系统上限**。学校可通过 **M0502 角色管理**自行新增角色、改名、调整授权；预置基线只解决"开箱即用"，不限制学校按实际组织架构扩展。
2. **新增角色必须同时配置三项，缺一不可**：①**菜单授权**；②**按钮授权**；③**三级数据范围**（本人 SELF / 本年级 GRADE / 全校 ALL）+ **归属类型**（组织型 / 关系型 / 角色授权型）。只配菜单不配数据范围的角色**不允许存在**。
3. **服务端硬约束（越权漏洞入口，必须实现）**：角色保存时服务端校验——**未配置完整数据范围的角色，不允许被授予任何「列表 / 详情 / 导出」类菜单**；若历史数据或绕过前端直接调用接口仍有此类角色，该角色访问对应接口一律**按最小权限（本人 SELF）处理，并打告警日志**。前端隐藏不作为安全边界（对齐 docs/01 AC-E5-1）。
4. **预置角色编码（`R-*`）不允许删除**，允许改名与调整授权；学校自建角色建议使用 **`R-CUSTOM-*`** 前缀，避免与预置编码冲突、便于升级时区分。
5. **新增角色不改变三级数据权限模型本身**：仍是 SELF / GRADE / ALL 三级，不新增第四级（对齐决策 2）；新增角色只是往既有三级里"加一个授权主体"。

**验收标准（角色可扩展性）：**
- AC-RBAC-1：管理员在 M0502 新建角色并同时配置菜单 / 按钮 / 三级数据范围后保存即时生效；三项中任一项缺失时**保存被拒并指明缺失项**。
- AC-RBAC-2：数据范围未配置完整的角色被授予「列表 / 详情 / 导出」类菜单时——保存校验拒绝（前端同步拦截）；即便通过其它途径被授予，接口层按**最小权限（本人 SELF）**返回并打**告警日志**。
- AC-RBAC-3：预置角色 `R-*` 的删除操作被服务端拒绝，改名与调整授权正常；自建角色使用 `R-CUSTOM-*` 前缀，与预置编码不冲突。
- AC-RBAC-4：任一角色（含自建角色）的数据范围取值只有 SELF / GRADE / ALL 三级，系统中不存在第四级。

## 账号安全与生命周期基线（漏洞补写）

### C8 账号安全
- **初始密码**：管理员批量导入用户（学生/家长/教师）时生成**随机初始密码**，用户首次登录**强制修改**。
- **密码复杂度**：最小长度 ≥ 8 位，至少含字母与数字（可按学校安全规范调整）。
- **登录失败锁定**：连续失败 N 次（默认 5）锁定账号，管理员可解锁；解锁后重置失败计数。

### B6 学生账号生命周期
- 学生账号状态：在读 / 毕业 / 转学 / 离校 / 休学。
- 离校处置：停用账号（不可登录）、解除 `student_parent` 关联、数据归档标记（不物理删除，见 docs/04 §1.9）。
