> 阶段：Phase 1 需求（第二业务域）| 产出人：教育产品专家（许清楚）| 门禁：门禁 1（需求门禁）
> 场景：教务域——排课 / 查看课表 / 调课 / 代课 / 请假代课
> 修订记录：自动排课（REQ-F5）纳入首版；代课/请假代课指派（REQ-H5/H6）纳入首版。

## 一、目标用户与场景（校长 / 教务 / 教师）

### 校长（管理视角）
1. **全校课表总览**：看全校各班课表、教师周课时分布。
2. **排课质量监控**：课表完整率、排课冲突数、软约束违规统计。
3. **调课/代课统计**：调课次数、代课次数、请假代课频次、原因分布。

### 教务（执行/管理视角）

> **业务称谓，非独立角色**：「教务处 / 教务」为岗位职责称谓，**执行主责由 R-DEAN 教务主任承担**（排课编排 / 课表发布 / 调课代课审批 / 教学运行统计，数据范围=**全校**）；**R-VP 分管教学副校长**保留全校查看与**重大变更审批**（学期课表整体重排、跨年级课时调整等）。二者分工不重叠——R-DEAN 主执行，R-VP 主审批与监督。

1. **排课基础数据维护**：教师任课表、班级、场地（统一场地对象 space，见 docs/04 §1.11）、节次。
2. **自动排课 + 手动微调**：一键生成课表（满足硬约束），拖拽微调兜底，再校验后发布。
3. **调课/代课/请假代课审批**：审核申请，通过后自动改课表。

### 教师（执行视角）
1. **查看课表**：本人课表 / 本班课表，1–2 步即见。
2. **调课申请**：选课→选目标时段→提交，≤3 步。
3. **请假代课**：请假并申请代课指派，≤3 步。

## 二、需求清单

### F. 排课管理（教务为主）
- **REQ-F1｜排课基础数据维护**：教师任课表、班级、场地（取自**统一场地对象 space**，见 docs/04 §1.11，含 CLASSROOM/LAB/MEETING_ROOM/SPORT_VENUE）、节次。教务。P0。
- **REQ-F2｜手动排课**：拖拽/录入排课，保存时冲突校验。教务。P0。
- **REQ-F3｜冲突校验规则引擎**：硬约束即时拦截，软约束提示可放行。教务+开发。P0。
- **REQ-F4｜课表发布与版本**：发布为正式课表，版本关联「**学期 + 生效周**」——学期取自 docs/04 §1.8 学期字典，**生效周必须落在该学期的周次范围内**，并带版本号；据此可按「当前学期」聚合出该学期课表。**课表发布 / 调课生效时须将该「场地 + 时段」写入统一场地对象 space 的占用记录（docs/04 §1.11）——课表占用即场地占用的权威来源**（预约类请求据此校验，见 docs/04 §1.12）。教务。P0。
- **REQ-F5｜自动排课引擎**【新增】：基于任课表/班级/教室/节次 + 硬约束/软约束，一键生成课表；生成后拖拽微调，微调后再校验；结果发布。教务。P0。

### G. 课表查看（教师/校长）
- **REQ-G1｜教师个人课表**：本人周课表。教师。P0。
- **REQ-G2｜班级课表**：班主任/教师看本班课表。班主任/教师。P0。
- **REQ-G3｜全校课表总览与课时统计**：全校课表、教师周课时分布。教务+校长。P1。
- **REQ-G4｜多视图切换**：周/日/列表三态。全体。P1。

### H. 调课/代课/请假管理（教师/教务）
- **REQ-H1｜调课申请**：选课→选目标时段→填原因，≤3 步。教师。P0。
- **REQ-H2｜调课审批**：教务/年级组长通过或驳回。教务/年级组长。P0。
- **REQ-H3｜调课联动更新**：审批通过自动更新课表并通知。教师+教务。P0。
- **REQ-H4｜调课记录与统计**：校长看调课次数/原因/时段分布。校长。P1。
- **REQ-H5｜代课安排**【新增】：某节课由其他教师代上，复用状态机（发起→审批→生效→课表标注代课人）。教师/教务。P0。
- **REQ-H6｜教师请假代课指派**【新增】：请假→指派代课教师→审批→课表更新。教师/教务。P0。

## 三、验收标准（含两条硬指标）

**两条硬指标：**
- 硬指标①【校长端】：任一核心教务指标（课表完整率/教师周课时分布/调课代课次数/排课冲突数/软约束违规数）无需离开系统追问。
- 硬指标②【教师端】：任一高频事务（查看本人课表、提交调课申请、提交请假代课）≤3 步。

### 排课
- AC-F1-1：录入任课表/班级/教室/节次后，排课界面可正常取用。
- AC-F2-1：硬约束冲突（同教师/同班级/同教室同时段）即时拦截并指明，不允许保存。
- AC-F3-1：软约束（连堂超限/体育课时段/单日课时超限）提示但可放行。
- AC-F3-2：班主任/教研活动预留时段被占用时提示。
- AC-F4-1：课表发布带**版本号 + 学期 + 生效周**，教师端即时可见；生效周不落在所选学期周次范围内时**服务端拒绝发布**；可按「当前学期」查询到该学期课表（对齐 docs/04 §1.8「学期 ⊇ 周次」，教务域不豁免学期口径）。
- **AC-F4-2**：课表发布成功（含调课/代课审批通过后生效）时，服务端将涉及的「场地 + 时段」写入**统一场地对象 space 的占用记录**（docs/04 §1.11），该占用作为实验预约/会议室预约/赛事排期的冲突校验基准（docs/04 §1.12）。
- **AC-F4-3【补写 C9】**：并发发布同一「学期 + 生效周」课表时，服务端以**版本号乐观锁**校验——提交版本号落后于库中当前版本的一律**拒绝发布并提示刷新**，防止后发覆盖先发导致课表回退。
- **AC-F4-4【补写 场地占用补偿】**：课表发生变更（调课生效 / 版本重排 / 重新发布）导致**已生效的场地预约被排课占用覆盖**时，服务端须**主动比对出受影响的预约记录**，并向对应预约人推送**消息中心通知**（走 docs/15 统一消息接口，**未推送视为不通过**）。
  - 【已知限制】首版排课为权威源，**预约不反向阻断排课**；双向互斥与预约优先策略列 **V2.0**（见 docs/04 §1.12）。
- AC-F5-1【新增】：一键排课后满足**全部硬约束**（无教师/班级/教室冲突、学科匹配、周课时达标），给出校验通过报告。
- AC-F5-2【新增】：自动排课生成耗时 P95 ≤ 30 秒（规模：班级≤60、教师≤200、日节次≤10、周≤5天）。
- AC-F5-3【新增】：生成结果支持拖拽微调，微调后再校验；有冲突拦截并指明，无冲突可发布。
- AC-F5-4【新增】：硬约束无解时返回「无解报告」，指明无法满足的约束与冲突明细，不静默失败。

### 课表查看
- AC-G1-1：教师查看本人课表 ≤2 步。✅硬指标②
- AC-G2-1：班主任仅能看本人所带班级课表。
- AC-G3-1：校长查看全校课表与教师周课时分布，无需问教务。✅硬指标①
- AC-G3-2：校长查看课表完整率、冲突数、软约束违规数，无需问教务。✅硬指标①
- AC-G4-1：课表周/日/列表三态切换，数据一致。

### 调课/代课/请假
- AC-H1-1：教师提交调课申请 ≤3 步。✅硬指标②
- AC-H2-1：审批人通过/驳回 ≤2 步。
- AC-H3-1：调课审批通过后课表自动更新，相关教师即时收到通知。
- AC-H3-2【补写 E1】：调课/代课审批通过、写回课表前，服务端**二次校验目标时段无冲突**；若审批期间目标时段已被其他调课占用，则拦截并回退（不产生新冲突）。
- AC-H4-1：校长查看调课次数/原因/时段分布，无需问教务。✅硬指标①
- AC-H5-1【新增】：代课安排全流程闭环（提交→审批→生效→课表标注代课人）。
- AC-H5-2【新增】：请假代课指派提交 ≤3 步。✅硬指标②
- AC-H5-3【新增】：请假代课审批通过后，课表该节标注代课教师与请假原因，双方均收到通知。
- AC-H5-4【新增】：代课指派时代课教师该时段已有课时，即时拦截并提示冲突。

## 四、明确排除项（本次不做什么）

1. 不含成绩管理、考试安排、考勤、学籍。
2. 不含走班制/分层教学复杂排课（首版仅行政班固定课表）。
3. 不含跨校区/多场地复杂调度。
4. 不含智能调课推荐（AI 推荐最优调课方案）。
5. 不含手机原生 App（沿用 Web 响应式）。
6. 不含外部日历同步。
7. 调课/代课/请假沿用固定线性审批，不含会签/转签/条件分支。

> 注：原排除项「不含自动排课算法」已撤销——自动排课（REQ-F5）纳入首版；原 V2.1「代课/请假」已提前到首版（REQ-H5/H6）。

## 五、未来 2–3 版本扩展方向 + 三级权限数据范围表

### 未来版本扩展方向
- **V2.0（走班制）**：分层教学/选课走班排课，排课引擎扩展「行政班+走班」混合模型。
- **V2.1（排课引擎增强）**：软约束权重可配置、多目标优化（课时均衡/连堂惩罚/教师偏好）。
- **V2.2（考试安排）**：监考排班、考场编排，复用排课约束引擎。
- **V3.0（成绩模块）**：成绩录入/分析，继续复用三级权限与状态机模板。

## 附：排课引擎硬/软约束完整清单（REQ-F5 引擎输入）

### 硬约束（必须全部满足，违反即无解/报错）

| 编号 | 约束 | 说明 |
| --- | --- | --- |
| H1 | 教师时间冲突 | 同一教师同一节次不能两门课 |
| H2 | 班级时间冲突 | 同一班级同一节次不能两门课 |
| H3 | 教室/场地冲突 | 同一教室同一节次不能两个班级 |
| H4 | 教师学科匹配 | 教师只排其任教学科 |
| H5 | 班级学科周课时达标 | 每班每学科周课时 = 任课表规定 |
| H6 | 教室容量约束 | 班级人数 ≤ 教室容量 |
| H7 | 教室类型匹配 | 体育→操场、实验→实验室 |

### 软约束（尽量满足，违反计分/提示，权重可配）

| 编号 | 约束 | 说明 |
| --- | --- | --- |
| S1 | 学科连堂限制 | 同科同天不超过 N 节 |
| S2 | 体育课时段限制 | 不排第1节/午休后第1节 |
| S3 | 预留时段 | 班主任/教研活动时段不排课 |
| S4 | 教师日课时上限 | 单日不超过 M 节 |
| S5 | 教师周课时均衡 | 均匀分布到各天 |
| S6 | 主科优先上午 | 语数英优先上午 |
| S7 | 跨教室缓冲 | 连续跨教室/楼层提示 |

### 输入/输出契约（供架构专家技术选型）

- **输入**：任课表(教师×班级×学科×周课时)、班级(班级×人数)、教室(教室×容量×类型)、节次(节次×时间)、硬约束集、软约束集(带权重)。
- **输出**：课表方案(班级×节次→教师×学科×教室) 或 无解报告(无法满足的约束+冲突明细)；生成统计(满足硬约束数、软约束违规数、耗时)。
- **技术选型**（CSP/OR-Tools/自研求解器）由架构专家在 ADR 阶段决策，PRD 只锁需求与约束契约。
