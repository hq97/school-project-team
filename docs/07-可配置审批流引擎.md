# 轻量级可配置审批流引擎（REQ-D3 升级）

> 阶段：Phase 1 需求（跨域修订）| 产出人：教育产品专家（许清楚）
> 影响域：后勤域（REQ-B2/C2）+ 教务域（REQ-H2/H5/H6）+ 通用基础（REQ-D3）
> 性质：把「固定线性审批」的**节点与审批角色**做成可配置，不引入复杂审批流能力。

---

## 一、REQ-D3 升级全文

**REQ-D3｜轻量级可配置审批流引擎**（目标用户：系统管理员，P0）

管理员在后台定义「流程模板」，业务类型绑定流程模板，审批人/流程不硬编码：

1. **流程模板**：流程名称、适用业务类型、有序节点列表、启用状态。
2. **流程节点**：每个节点指定「审批角色」（可配置），节点保持**固定线性**：提交 → 审批[可配置 1 级或多级] → 执行/完成。
3. **业务绑定**：每个业务类型（采购、领用、报修、调课、代课、请假代课）绑定一个流程模板。
4. **改配置即生效**：修改流程模板后，**新申请**按新流程走，不改代码；**进行中的申请**沿用创建时模板快照继续流转（保证历史实例确定性）。
5. **驳回规则**：任一级驳回即退回发起人（可重新提交，按当前最新模板流转）或终止（由模板配置驳回策略）。

### 数据模型契约（供架构专家实现，需求层锁定）

| 模型 | 字段 |
| --- | --- |
| 流程模板 flow_template | id、名称、适用业务类型、节点列表(有序)、启用状态、版本 |
| 流程节点 flow_node | id、模板id、顺序号、节点名、审批角色(role_code)、超时阈值(可选) |
| 业务绑定 | business_type → flow_template_id |
| 流程实例 flow_instance | 业务对象id、模板快照、当前节点序号、状态、审批历史(每级审批人/结论/时间/意见) |

## 二、各审批需求表述更新（硬编码审批人 → 流程模板配置）

**后勤域：**
- **REQ-B2｜领用审批**：由**流程模板绑定的审批角色**对待办申请通过/驳回，驳回需填原因。
- **REQ-C2｜报修分派与处理**：由**流程模板配置的处理角色**对报修工单分派维修人、更新状态直至完成。

**教务域：**
- **REQ-H2｜调课审批**：由**流程模板配置的审批角色**通过或驳回（驳回必填原因）。
- **REQ-H5｜代课安排**：复用调课状态机，审批环节由**流程模板配置的审批角色**审批。
- **REQ-H6｜请假代课指派**：请假→指派代课教师→由**流程模板配置的审批角色**审批→课表更新。

> 统一原则：所有审批类需求不再写死具体岗位，一律表述为"由流程模板配置的审批角色审批"；具体是后勤主管/年级组长/教务主任，由管理员后台配置决定。

## 三、补充验收标准（AC-D3 系列）

- **AC-D3-1**：管理员可新建/编辑流程模板，配置节点列表（增删节点、调顺序）与每节点审批角色，保存即时生效。
- **AC-D3-2**：每个业务类型绑定一个流程模板，业务发起时按绑定模板流转。
- **AC-D3-3**：修改流程模板后，**新申请**按新流程走，**进行中申请**沿用创建时模板快照，无需改代码。
- **AC-D3-4**：审批角色数据范围仍强制校验——审批人范围必须覆盖申请单归属范围，越权审批被服务端拒绝（40303）。
- **AC-D3-5**：多级审批（如 提交→年级组长→教务主任→完成）可配置并正确逐级流转，每级审批留痕（审批人/结论/时间/意见）。
- **AC-D3-6**：某审批节点角色下无可用人员时，系统提示配置异常，不允许提交/流转卡死，需管理员补配。
- **AC-D3-7**：驳回策略可配置（退回发起人可重提 / 直接终止），按模板配置执行。
- **AC-D3-8**【补写 E2】：多级审批中**每一级审批角色数据范围均须覆盖申请单归属**（逐级校验），任一不覆盖即该级不可审批、流程卡住并提示配置异常（对齐 AC-D3-6）。

## 四、排除项边界（不越界，明确保留）

**仍不含复杂审批流引擎**，流程为**固定线性**，明确排除：
- 不含会签（多人同时审批）、或签（任一人审批即过）。
- 不含条件分支、审批路由规则。
- 不含转签、代理审批、撤回后他人接管。
- 不含流程版本回滚/灰度（模板修改仅影响新申请，进行中实例用快照）。

> 本修订只把「固定线性审批的节点与审批角色」做成可配置，**不引入**会签/或签/分支/转签/代理等复杂能力。

## 五、未来 2–3 版本扩展方向 + 三级权限数据范围表

### 未来版本扩展方向

> 本节登记的是**首版排除项解除后的演进方向**；V1.0 仍严格保持「固定线性审批」，本节全部内容**均不在首版范围内**，不得反向影响第四节排除项边界。

- **V2.0（并行会签 / 或签）**：节点支持多人并行审批——会签（全部通过才流转）、或签（任一人通过即流转）、按比例通过（如 2/3 通过），支持会签人顺序与意见汇总。对应解除排除项「不含会签（多人同时审批）、或签（任一人审批即过）」。
- **V2.1（条件分支与路由规则）**：按业务字段条件（金额阈值 / 资产类型 / 请假天数 / 数据范围）自动选择审批路径与节点数，支持「条件节点 + 默认分支」。对应解除排除项「不含条件分支、审批路由规则」。
- **V2.2（加签 / 转办 / 代理审批）**：审批过程中前加签、后加签、转办他人、代理人设置（含假期代理自动生效）。对应解除排除项「不含转签、代理审批、撤回后他人接管」。
- **V3.0（审批时效 SLA 与自动升级）**：节点超时阈值（复用 docs/03 M0505 `DICT-OVERDUE-DAYS` 超期天数配置）触发三级动作——提醒 → 自动升级到上级角色 → 自动通过/自动退回；与 docs/15 消息中心超期预警联动，SLA 达成率进入 docs/14 数据大屏（服务校长端硬指标①）。
- **V3.1（流程版本灰度与回滚，可选）**：模板版本灰度发布（按比例 / 按年级放量）与回滚。对应解除排除项「不含流程版本回滚/灰度」——解除时须重新设计「进行中实例用快照」的确定性约束（AC-D3-3），不得破坏历史实例可追溯性。

> 演进纪律：以上任一项落地时，**AC-D3-4 / AC-D3-8「每级审批角色数据范围须覆盖申请单归属」的越权校验不得削弱**，本节只扩展流转形态，不放宽数据边界。

## 六、对下游的输入提示

- **设计阶段**：系统管理新增「流程模板管理」菜单——**M0507 流程模板管理**（`/system/flow-templates`，已并入 docs/03 菜单树），**仅 R-ADMIN 可见可维护**，按钮 `BTN-FLOW-TPL-EDIT`（docs/03 决策 15：M0505 已定为「数据字典管理」，流程模板管理顺延为 M0507，docs/03 决策 14/15 与本处同步）；审批节点以角色为最小授权单元，渲染时按"当前节点审批角色 → 命中该角色的用户"生成待办。
- **开发阶段**：服务端在每次审批动作前校验：①当前用户是否命中当前节点审批角色；②其数据范围是否覆盖申请单归属；任一不满足即 40302/40303。
- **数据权限说明书**：审批人数据范围强制校验规则（第五节第 4 条）与此处 AC-D3-4 一致，无需改动。
