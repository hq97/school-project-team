# 中学校务数字化平台 · 首个切入场景 PRD（修订版）

> 阶段：Phase 1 需求 | 产出人：教育产品专家（许清楚）| 门禁：门禁 1（需求门禁）
> 场景：采购/项目进度看板 + 物资领用/报修预约（后勤向）
> 修订记录：在已确认内容基础上，增补「系统管理（RBAC）」模块（E）与对应验收标准（AC-E）、排除项 10–12

## 一、目标用户与场景

### 校长视角（管理视角）——"要汇总、要趋势、要异常，最怕看数字还要去微信问人"

1. **采购/项目进度总览**：一眼看到全校**当前学期**采购项目数、预算总金额、已执行金额、各状态数量分布。完成标准：所有数字在系统内直接可见，无需问任何人。
2. **异常提醒**：系统主动推送「超期未到货」「预算执行超阈值」「审批滞留超 N 天」「报修超时未处理」清单。
3. **趋势分析**：采购金额趋势、物资领用频次趋势、报修量趋势、报修平均响应时长——**默认按「学期」口径**，趋势图 / 报表提供「学期 / 自然月」维度切换器。
4. **物资/库存监控**：库存预警、高频领用物资 TOP 榜、人均领用概览。

> **时间口径（统一）**：本模块所有统计**默认按「学期 + 周次」**聚合，趋势图 / 报表提供「**学期 / 自然月**」**维度切换器**；自然月**仅为展示维度**（兼顾财务月报阅读习惯），**不改变数据归属、聚合结果与权限判定口径**（口径依据 docs/04 §1.8「统一时间口径」，本文档只引用不自造时间维度）。

### 教师视角（执行视角）——"要少跑腿、少填表、少问人，最烦办一件事点七八下"

1. **物资领用申请**：选物资→填数量→提交，全程 ≤3 步。
2. **报修预约**：选位置/设备→描述问题→提交，全程 ≤3 步。
3. **申请/报修状态追踪**：我的申请、我的报修，状态一目了然。
4. **采购需求发起**：提交采购需求→跟踪审批→确认到货，同一入口闭环。

> 切入场景选型结论：后勤向「采购看板 + 物资领用 + 报修预约」是标准的「申请—审批—状态追踪」闭环，天然具备模板复制价值。

## 二、需求清单

### A. 采购/项目进度看板（校长端为主）
- **REQ-A1｜采购项目进度总览**：校长查看全校采购项目列表与状态分布卡片。校长。P0。
- **REQ-A2｜项目状态流转跟踪**：单项目状态时间线（待审批→审批中→已下单→已到货→已验收）。校长+发起教师。P0。
- **REQ-A3｜异常/超时提醒**：超期未到货、审批滞留、预算超阈值自动生成异常清单并推送。校长。P0。
- **REQ-A4｜预算执行监控**：按项目/部门展示预算额度、已执行、执行率，超阈值标红。校长。P1。
- **REQ-A5｜趋势统计报表**：采购金额、领用频次、报修量、响应时长固定报表——**默认「学期」口径**，提供「**学期 / 自然月**」**维度切换器**（自然月仅作展示维度，口径依据 docs/04 §1.8）。校长。P1。

### B. 物资领用（教师端为主）
- **REQ-B1｜物资领用申请**：选物资（取自统一资产台账 asset，assetType=物资）→填数量→提交，≤3 步。教师。P0。
- **REQ-B2｜领用审批**：审批人通过/驳回，驳回填原因。审批人。P0。
- **REQ-B3｜领用状态查询**：教师查看申请状态与驳回原因。教师。P0。
- **REQ-B4｜资产台账查询与预警**：教师查可领用资产（统一资产台账 asset）；校长看低库存/临期预警。教师+校长。P1。

### C. 报修预约（教师端为主）
- **REQ-C1｜报修提交**：选位置/设备→描述/拍照→提交，≤3 步。教师。P0。
- **REQ-C2｜报修分派与处理**：后勤分派维修人、更新状态至完成。后勤。P0。
- **REQ-C3｜报修状态追踪**：教师查看报修进度。教师。P0。
- **REQ-C4｜报修响应时长统计**：校长看平均响应时长与超时工单。校长。P1。

### D. 通用基础能力（为复制埋点）
- **REQ-D1｜角色与三级权限体系**：本人/本年级/全校三级数据边界，登录即生效。全体。P0。
- **REQ-D2｜站内消息通知**：审批结果、超时预警等站内通知触达。全体。P0。
- **REQ-D3｜状态字典与流程模板抽象**：「申请—审批—状态追踪」抽成通用状态机，字段与流转可配置。架构/开发。P0。

### E. 系统管理（RBAC）——【本次新增】
> 关系说明：E 模块是 REQ-D1 的落地载体。数据权限「本人/本年级/全校」由角色绑定；部门/年级/教研组作为数据范围组织载体。菜单权限与数据权限分层解耦。

- **REQ-E1｜用户管理**：系统管理员对教职工账号增删改查、启停用、关联部门与角色。系统管理员。P0。
- **REQ-E2｜角色管理**：自定义角色；角色绑定菜单权限（含按钮级）与数据权限范围（本人/本年级/全校）。系统管理员。P0。
- **REQ-E3｜菜单管理**：动态菜单与按钮级权限配置，不同角色看到不同菜单与按钮。系统管理员。P0。
- **REQ-E4｜部门管理**：组织架构维护，支持部门/年级/教研组树形结构增删改。系统管理员。P0。

## 三、验收标准（含两条硬指标）

**两条硬指标（需求门禁，缺失即阻断）：**
- 硬指标①【校长端】：任一核心指标无需离开系统去微信或电话追问。
- 硬指标②【教师端】：任一高频事务操作步数 ≤3 步。

> **时间口径（统一，适用于本节全部 AC）**：统计与趋势**默认按「学期 + 周次」**聚合；趋势图 / 报表须提供「**学期 / 自然月**」**维度切换器**，自然月**仅为展示维度**，不改变数据归属、聚合结果与越权判定（docs/04 §1.8）。本文档原「月度采购金额」「本月项目数」等自然月口径表述已统一改为学期口径。

### 采购/看板
- AC-A1-1：校长打开总览即可看到**当前学期**项目数、预算总额、执行金额、各状态数量。✅硬指标①
- AC-A2-1：任意项目可点开状态时间线，节点时间与操作人完整。✅硬指标①
- AC-A3-1：超期未到货自动标红并推送。✅硬指标①
- AC-A3-2：审批滞留自动生成清单。✅硬指标①
- AC-A4-1：预算执行率超阈值自动标红。✅硬指标①
- AC-A5-1：报表页直接看趋势，无需二次加工；默认「学期」口径并提供「学期 / 自然月」维度切换器——切换维度不改变可见数据与越权判定（docs/04 §1.8）。✅硬指标①

### 物资领用
- AC-B1-1：物资领用申请 ≤3 步。✅硬指标②
- AC-B1-2：库存不足申请时拦截或提示。
- AC-B1-3【补写 C9】：库存扣减并发不超卖——多人同时领用最后一件资产，仅一人成功，其余返回库存不足（availableQty 原子扣减，见 docs/04 §4.2 D 段）。
- AC-B2-1：审批处理 ≤2 步。
- AC-B3-1：教师自见申请状态与驳回原因。✅硬指标①

### 报修预约
- AC-C1-1：报修提交 ≤3 步。✅硬指标②
- AC-C1-2：报修支持拍照/选类型，生成唯一工单号。
- AC-C2-1：工单分派处理留痕。
- AC-C3-1：教师自见报修进度。✅硬指标①
- AC-C4-1：校长自见响应时长与超时清单。✅硬指标①

### 通用基础
- AC-D1-1：三级可见范围按权限表生效（越权被拒）。
- AC-D2-1：审批结果/预警/驳回原因站内通知触达。
- AC-D3-1：状态字典与流程模板可配置复用。

### 系统管理（RBAC）——【本次新增】
- AC-E1-1：新建用户关联部门+角色后，登录即按角色生效。
- AC-E2-1：新建/编辑角色分配菜单+数据范围后即时生效。
- AC-E2-2：「本年级」数据范围越级访问被服务端拒绝。
- AC-E3-1：角色菜单权限变更即时渲染。
- AC-E3-2：按钮级权限前端隐藏 + 接口服务端拒绝。
- AC-E4-1：部门树增删改 + 挂靠生效。
- AC-E4-2：有子节点/人员的部门禁止硬删。
- AC-E5-1：越权访问一律服务端校验拒绝，前端隐藏不作为安全边界。

## 四、明确排除项（本次不做什么）

1. 不含移动 App / 原生客户端（首版 Web 响应式）。
2. 不含复杂审批流引擎（仅固定线性审批）。
3. 不含财务系统对接与实际支付。
4. 不含多校联合 / 跨校数据互通 / 区级上报。
5. 不含历史数据迁移（全新项目）。
6. 不含工资、人事考勤、排课、成绩等超出后勤场景的业务。
7. 不含 AI 智能预测。
8. 不含自定义报表设计器。
9. 不含外部电子签章、短信网关、邮件网关（仅站内通知）。
10. **不含字段级数据权限**【新增】：数据权限到记录级，不做同表字段级隐藏。
11. **不含多租户**【新增】：单校单实例，不做多学校数据隔离。
12. **不含组织层级驱动动态审批链**【新增】：审批人由角色/流程模板显式指定。
13. **不含教师考勤（扫码考勤）**【补写 A3】：教师考勤属人事/考勤域，不在本阶段六大业务域内，留后续版本补充。

## 五、未来 2–3 版本扩展方向 + 三级权限数据范围表

### 未来版本扩展方向
- **V1.1（模板复制验证）**：复用模板接入场地预约、设备借用、通知回执。
- **V1.2（教务域）**：调课、代课、请假审批，同一状态机接入。
- **V2.0（德育域）**：学生请假、违纪登记、评优审批；引入家长/学生角色。
- **V2.x（科教/体育域）**：实验室预约、器材借用、竞赛报名，完成六大业务域。
- **V2.x（权限增强，可选）**：字段级权限、组织层级驱动审批、多校区/多租户。

### 三级权限数据范围表（本人 / 本年级 / 全校）

> 组织维度说明：角色（REQ-E2）决定权限级别，部门（REQ-E4）决定归属范围，二者共同约束一条记录对谁可见。

| 数据对象 | 本人 | 本年级（年级组长/教研组长） | 全校（校长/后勤主管） |
| --- | --- | --- | --- |
| 采购项目记录 | 仅本人发起可见 | 本年级/本教研组汇总可见 | 全部可见（含金额与明细） |
| 采购预算数据 | 本人项目预算可见 | 本组项目预算可见 | 全校额度+执行率可见 |
| 物资领用申请 | 仅本人可见 | 本年级领用汇总可见 | 全部记录+汇总可见 |
| 报修工单 | 仅本人可见 | 本年级汇总可见 | 全部+响应时长可见 |
| 资产台账 asset | 仅可查可领用资产 | 同本人 | 全库资产+预警阈值可见 |
| 审批记录 | 本人相关可见 | 本组审批汇总可见 | 全部可见 |
| 异常/超时提醒 | 本人相关可见 | 本组相关可见 | 全校异常清单可见 |
