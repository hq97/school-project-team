# 中学校务数字化平台 · 党政办公室域 PRD

> 阶段：Phase 1 需求（第四业务域）| 产出人：教育产品专家（许清楚）| 门禁：门禁 1（需求门禁）
> 场景：通知公告 / 公文流转 / 会议管理 / 值班安排 / 用印与介绍信审批
> 复用：可配置审批流（docs/07 REQ-D3）、RBAC（docs/03）、三级权限（docs/04，返回码 401/40301/40302/40303/40304）

---

## 一、目标用户与场景（校长 / 党政办 / 教职工）

### 校长（管理视角）——要回执、要时效、要异常
1. **公告送达看板**：公告发布数、已读率、未读名单。
2. **公文流转时效**：收文/发文数量、办理时长、滞留公文。
3. **值班与会议**：值班异常、会议纪要归档情况。

### 党政办（执行/管理视角）——要留痕、要流转、要归档
1. **公告发布与撤回**：发布/撤回通知公告，查看已读回执。
2. **公文收发与流转**：收文/发文登记、拟办、批示、传阅。
3. **会议与值班**：会议室预约、会议通知、纪要归档、值班表编排。

### 教职工（执行视角）——要少跑腿、要知悉
1. **查看公告并已读**：≤2 步即见并留已读回执。
2. **会议室预约 / 换班申请 / 用印申请**：≤3 步提交。

## 二、需求清单（REQ-L，标 P0/P1）

### L. 党政办公室
- **REQ-L1｜通知公告发布**：党政办发布通知公告（标题/正文/附件/**可见角色集合**/置顶），发布即推送。可见范围走**角色维度配置**（发布时选可见角色，如全体教职工/班主任/体育教师/学生/家长），不按组织型三级数据范围判定。目标用户：党政办。P0。
- **REQ-L2｜公告撤回与已读回执**：已发布公告可撤回；记录每个可见用户的已读状态（已读/未读/已读时间），提供未读名单。**已读口径统一（唯一口径）**：无论用户从「通知公告 M1201」进入，还是从「消息中心 M0105」点击该公告的消息跳转进入，**均由本域记录同一份已读回执**；消息中心不独立维护公告已读计数（见 docs/15 AC-MS8-1、docs/04 §3.10）。目标用户：党政办。P0。
- **REQ-L3｜公文收文登记**：党政办登记收文（来文单位/文号/标题/密级/紧急程度/扫描件），拟办意见。目标用户：党政办。P0。
- **REQ-L4｜公文发文登记**：党政办登记发文（文号/标题/主送/抄送/签发人/正文），归档。目标用户：党政办。P0。
- **REQ-L5｜公文拟办/批示/传阅**：收文进入拟办→批示→传阅流程，由**流程模板配置的审批角色**流转，全程留痕。目标用户：审批角色成员。P0。
- **REQ-L6｜会议室预约**：教职工预约会议室（会议室取自**统一场地对象 space**，`spaceType=MEETING_ROOM`，见 docs/04 §1.11）；**提交时须先读取该「会议室 + 时段」的课表占用做冲突校验**（命中则拒绝，见 docs/04 §1.12），合格后再按并发规则竞争同一时段。冲突即时拦截，复用场地预约模板。目标用户：教职工。P0。
- **REQ-L7｜会议通知**：会议发起（时间/地点/议题/参会人），参会人收到通知并回执（参加/请假）。目标用户：党政办/发起人。P0。
- **REQ-L8｜会议纪要归档**：会议纪要与决议归档，可检索。目标用户：党政办。P1。
- **REQ-L9｜值班表编排**：党政办编排值班表（日期/时段/值班人/电话），发布后教职工可查。目标用户：党政办。P0。
- **REQ-L10｜值班记录**：值班人填写值班记录（情况/交接事项）。目标用户：值班人。P0。
- **REQ-L11｜换班申请**：教职工提交换班申请（本人班次→目标班次/换班人），复用「申请-审批-状态追踪」，由**流程模板配置的审批角色**审批。目标用户：教职工。P0。
- **REQ-L12｜用印审批**：印章使用申请（用印事由/份数/文件），由**流程模板配置的审批角色**审批。目标用户：教职工。P0。
- **REQ-L13｜介绍信开具审批**：介绍信开具申请（事由/抬头/有效期），由**流程模板配置的审批角色**审批。目标用户：教职工。P1。
- **REQ-L14｜公文滞留预警**【补写 C10】：公文（收文/发文）进入后在可配阈值时长内未办结（默认 7 天，可由党政办配置），系统自动生成**滞留预警**，纳入 docs/04 §3.7「异常/超时提醒」统一数据对象，并走**消息中心（docs/15 REQ-MS5）**推送给党政办与当前办理人。目标用户：党政办/当前办理人。P1。

## 三、验收标准（含两条硬指标）

**两条硬指标：**
- 硬指标①【校长端】：任一核心党政指标（公告已读率 / 公文流转时效 / 值班异常 / 会议纪要归档）无需离开系统去微信或电话追问。
- 硬指标②【高频事务 ≤3 步】：教职工查看公告、会议室预约、换班申请、用印申请 ≤3 步。

**逐条可测试验收标准：**
- AC-L1-1：党政办发布公告（标题/正文/附件/可见范围/置顶）后，可见范围内用户即时收到。
- AC-L2-1：教职工打开公告即记为已读（**两条进入路径记录同一份回执**——从「通知公告 M1201」进入，或从「消息中心 M0105」点击该公告消息跳转进入），党政办可查已读/未读名单与已读时间，无需线下统计。✅硬指标①
- AC-L2-2：已发布公告可撤回，撤回后不再对用户展示。
- AC-L3-1：收文登记字段齐全（来文单位/文号/标题/密级/紧急程度/扫描件），保存即生成收文编号。
- AC-L4-1：发文登记后生成文号并归档，可检索。
- AC-L5-1：收文拟办→批示→传阅由流程模板配置的审批角色流转，每步留痕。
- AC-L6-1：教职工会议室预约（选会议室→选时段→提交）≤3 步，时段冲突即时拦截。✅硬指标②
- AC-L6-2【补写 C9】：会议室时段并发不超订——同一会议室同一时段并发预约仅一人成功，其余被拒（时段原子锁定）。
- **AC-L6-3【补写 场地占用】**：会议室预约提交时（**在并发竞争之前**），服务端先读取该「会议室 + 时段」的**课表占用**（docs/06 已发布课表）做冲突校验——命中课表占用一律**拒绝并返回 40901（场地已被课表占用）**，无需进入并发判定。**语义区别于 AC-L6-2**：L6-2 是与「其他预约请求」抢同一格（C9 并发），L6-3 是与「已排定的课表」冲突（排课优先单向校验）。反向（预约阻断排课）本期不做，列 V2.0（见 docs/04 §1.12）。
- AC-L7-1：会议通知发送后，参会人收到通知并回执，发起人可查回执情况。
- AC-L8-1：会议纪要归档后可检索，校长查看归档情况无需问党政办。✅硬指标①
- AC-L9-1：值班表编排发布后，教职工可按日期/人查询。
- AC-L10-1：值班人填写值班记录留痕。
- AC-L11-1：换班申请（选本人班次→选换班人→提交）≤3 步，审批通过后值班表自动更新。✅硬指标②
- AC-L12-1：用印申请（填事由/份数→提交）≤3 步，审批留痕。✅硬指标②
- AC-L13-1：介绍信申请由流程模板配置的审批角色审批，通过后生成介绍信编号。
- AC-L14-1：公文（收文/发文）超过阈值未办结自动生成滞留预警，推送党政办与当前办理人，并纳入 docs/04 §3.7 统一异常清单，校长可在大屏查看无需问党政办。✅硬指标①

## 四、明确排除项（本次不做什么）

1. 不含电子签章/CA 认证/防伪水印（用印仅流程登记，不接电子章）。
2. 不含公文的红头文件排版引擎（发文仅登记与附件归档，不做版式生成）。
3. 不含外部 OA/政务公文交换系统对接。
4. 不含视频会议系统对接（会议通知仅记录，不接会议平台）。
5. 审批沿用固定线性（REQ-D3），不含会签/或签/条件分支/转签/代理。
6. 不含手机原生 App（沿用 Web 响应式）。
7. 不含保密公文的分级加密存储（密级仅作字段登记，不做加密）。

## 已确认决策（2026-10-29，用户拍板）

1. **R-PARTY（党政办）→ 采纳补缺**：与 R-LOGISTICS/R-MORAL 同构（行政处室 OFFICE、数据范围全校），独立角色，不并入 R-VP。
2. **公告可见范围 → 角色维度配置**：发布时选可见角色集合，走 RBAC 角色授权，**不纳入组织型三级数据范围**（不做全校/本年级/本班的组织判定）。用户看到某公告 = 命中该公告可见角色 + 有公告菜单权限。
3. **值班换班审批人 → 流程模板配置**：默认绑定党政办角色审批，可配置。
4. **公文密级 → 仅字段登记不加密**：密级（内部/秘密/机密）作字段登记，不做分级加密存储。
