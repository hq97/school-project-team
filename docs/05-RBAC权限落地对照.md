# RBAC 权限落地对照表（菜单 / 角色 / 数据权限）

> 用途：明确「哪些能力直接用 vue-pure-admin 自带、哪些必须自建」，作为设计（Phase 3）与开发（Phase 4）的输入。
> 来源：综合 PRD E 模块（许清楚）+ ADR 关键裁决（高筑远）。

---

## 一、核心结论（一句话）

- **菜单 / 角色 / 按钮 / 部门**：vue-pure-admin 自带且**天然可配置**，直接用，不重造轮子。
- **数据权限（本人 / 本年级 / 全校）**：vue-pure-admin **不带**，是我们必须自建的核心，且**必须由服务端逐接口强制校验**。

---

## 二、逐项对照

| 能力项 | vue-pure-admin 自带？ | 是否可配置 | 校验位置 | 我们的处理 |
| --- | --- | --- | --- | --- |
| 用户管理 | ✅ 自带 | ✅ 可配置 | 前端表单 + 后端接口 | 直接用；扩展「关联部门 + 关联角色」字段 |
| 角色管理 | ✅ 自带 | ✅ 可配置 | 前端 + 后端接口 | 直接用；**扩展「数据范围」字段**（本人/本年级/全校） |
| 菜单管理 | ✅ 自带 | ✅ 可配置 | 前端 + 后端接口 | 直接用（动态路由 + 菜单树 + 图标/排序） |
| 按钮权限 | ✅ 自带（v-auth 指令） | ✅ 可配置 | **前端隐藏 + 后端接口再校验** | 直接用前端指令做隐藏；后端接口必须再做一次服务端校验 |
| 部门管理 | ✅ 自带（基础部门树） | ✅ 可配置 | 前端 + 后端接口 | 直接用；扩展为「部门 / 年级 / 教研组」树形组织 |
| **数据权限（本人/本年级/全校）** | ❌ **不自带** | ✅ 可配置（在角色上绑定数据范围） | **服务端 Guard 逐接口强制校验** | **自建**：角色加「数据范围」字段，后端按范围截断查询，前端只消费后端标记 |

---

## 三、关键边界（务必理解）

1. **「菜单/按钮权限」与「数据权限」是两层，必须解耦**：
   - 菜单/按钮权限 = 「能不能看到这个入口 / 能不能点这个按钮」 → vue-pure-admin 自带，可配置。
   - 数据权限 = 「看到多少数据（本人/本年级/全校）」 → 自建，服务端裁决。

2. **前端隐藏不作为安全边界**：按钮隐藏只是体验优化；真正防越权靠后端每个接口校验数据范围，返回统一 403 业务码（无操作权限 FORBIDDEN_ACTION / 数据越权 FORBIDDEN_SCOPE）。

3. **「可配置」的落地位置**：管理员在「角色管理」里给每个角色勾选菜单/按钮权限 + 选择数据范围（本人/本年级/全校），保存即生效。这部分操作界面 vue-pure-admin 自带，我们只需在后端给角色表加一个 `data_scope` 字段并在接口上强制读取它。

---

## 四、与 PRD / ADR 的对应

| 本文项 | PRD 需求 | ADR 裁决 |
| --- | --- | --- |
| 用户/角色/菜单/部门 | REQ-E1~E4 | 采纳 vue-pure-admin 基座 |
| 数据权限 | REQ-D1 + 三级权限表 | 服务端 Guard 双校验 + 403 业务码 |
| 按钮权限 | AC-E3-2 | 前端隐藏 + 接口服务端拒绝 |
