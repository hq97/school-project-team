## 零、总纲（先读这三条，其余是细则）

1. **Git 自第一个提交起纳入管理，禁止先写码后补 Git**（docs/02 §5.1 已裁定）。但在架构骨架未落地前不抢跑——首提交的内容由本文 §五规定。
2. **本项目的分支粒度不是"功能点"，而是"单场景闭环"**——分支策略必须服务「先跑通一个域，再复制到其余五域」这条主线（§1.5）。通用模板（feature/bugfix/release 三件套）不足以实现这条策略。
3. **合并前的权限抽查是一票否决，不是走流程。** 任一越权路径存在 → 阻断合并、回退给架构与实现专家，不接受"先合了回头补"。

## 一、分支策略

### 1.1 仓库形态

单仓 monorepo（docs/02 §5.1 裁定），顶层固定为：

```
school-project-team/
├── apps/server/            # NestJS 10 + TS（Prisma 在此）
├── apps/web/               # vue-pure-admin
├── deploy/                 # docker-compose.yml / nginx
├── scripts/                # migrate.sh / backup.sh
├── docs/                   # 需求与架构设计文档（01~16）
├── design/                 # 前端原型 + Vue 源码（设计阶段产物）
├── CHANGELOG.md            # 本文 §三
├── .gitignore / .gitattributes
└── README.md
```

### 1.2 长期分支（仅 3 类，全部受保护）

| 分支 | 生命期 | 用途 | 保护规则 |
| --- | --- | --- | --- |
| `main` | 永久 | **唯一发布源**，对应"可复制到新校"的交付版本 | 禁直推、禁 `--force`、仅从 `release/*` 合入 |
| `develop` | 永久 | 集成分支，所有临时分支从这里拉出、合回这里 | 禁直推、禁 `--force`、合入需满足 §1.4 四条前置件 |
| `release/<version>` | 发布窗口内（≤2 周） | 发布冻结：只收 `fix/` 与 `docs/`，**不收 `feat/`** | 例：`release/v0.1.0`；冻结期内只做缺陷与文档 |

规则：

- **不存在 `test` / `temp` / `dev2` / 人名 / 日期类长期分支。** 临时分支存活超过 **7 天**必须合回 `develop` 或删除，禁止长期存在的烂尾分支。
- 个人不得拥有长期分支。`main`/`develop` 只允许 fast-forwardable 合并，禁止改写已推送历史。

### 1.3 临时分支命名

```
<type>/<scope>[-<short-desc>]
```

- `type` 取自 §2.2 的 type 清单（小写）。
- `scope` 取自 §2.3 的 scope 取值清单（小写，中划线），**不得自造**。
- `short-desc` 可选，必须是具体场景（中划线分词），**≤40 字符**，禁止中文分支名、禁止无描述纯序号。

示例（真实可用）：

```
chore(骨架)      →  chore/repo-scaffold            # 脚手架与仓库配置
feat/platform    →  feat/perm-datascope-decorator  # @DataScope 装饰器与启动期校验
feat 样板域       →  feat/logistics-material-loop   # 后勤-物资领用单场景闭环
feat 样板域       →  feat/party-room-booking-loop   # 党政-会议室预约单场景闭环
fix              →  fix/space-occupancy-identity-leak
复制阶段          →  feat/copy-moral-leave          # 德育-请假（由样板域复制而来）
复制阶段          →  feat/copy-science-lab
docs             →  docs/04-scope-matrix-sync
build            →  build/web-vue-pure-admin
ci               →  ci/eslint-no-raw-query
```

**一个分支只做一件事。** 判定标准：这个分支的 diff 能否用一句 Conventional Commit 标题写完；写不完 → 拆分支。

### 1.4 保护分支规则（合入 `develop` / `release` / `main` 的前置件）

四条前置件缺一不可，缺一即不放行：

1. **Review 记录**：有检查项 / 有结论 / 有问题与责任人（对应门禁 5）。
2. **测试报告或本地验证说明**：覆盖本次改动的验收 AC + 越权场景（docs/04 §六 10 条）+ 并发场景（docs/02 §4.1 八个点）——三类场景任缺一类视为报告不全（对应门禁 6）。
3. **CHANGELOG 条目**：随本次合并更新，含 `Security` 分组（§三）。不允许攒到发布前补。
4. **§四 合并前抽查清单全绿**，且抽查结论写进 Review 记录。

合并方式：

- 一律 **`git merge --no-ff`**（保留分支边界，便于按场景回滚与按域审计）。**禁止把整个域 squash 成一个提交**——那会丢掉"哪个域、哪个接口改了权限"的可追溯性。
- 禁止 `--force` 推共享分支；禁止 rebase 已推送并被他人引用的分支（临时分支自己整理本地 commit 可以，但必须在合入前完成）。

### 1.5 【本项目核心】分支如何服务「单场景闭环 → 复制扩展」

六域六倍工作量如果平铺做，权限抽查会从"逐接口"退化成"抽查几个接口"，fail-closed 三层必然出现缝隙。因此分支按**三段跑道**编排：

#### 跑道 A：立柱（pillar）——唯一的跨层大分支，一次性合入

```
chore/repo-scaffold            # 仓库 / TS / ESLint / 目录骨架
feat/perm-datascope-decorator  # ②层：@DataScope + 启动期缺声明校验
feat/common-scope-query-builder# ③层：ScopeQueryBuilder + ESLint 封堵裸 SQL
feat/perm-global-guards        # ①层：AuthGuard / PermissionGuard 全局注册
```

- **为什么这是唯一被允许的跨层整体分支**：三层权限缺任何一层 fail-closed 都不成立，拆开合入会产生"半截权限"的空窗期。**除此处所述情形外，任何跨层的整体改动分支一律拒绝。**
- **合入 `develop` 的硬条件（比前置件更严）**：必须提供**可复现证据**证明：
  ① 启动期扫描存在（临时摘掉任一数据接口的 `@DataScope()` → bootstrap 失败并打印缺失清单）；
  ② ESLint 裸查规则生效（`prisma.$queryRaw` 写一个 demo → lint 报错）；
  ③ 全局 Guard 在 `main.ts` 注册（不得是逐个 Handler 可选挂载的 `@UseGuards()` 写法）。
  **没有这三条证据 → 阻断合并，直接回退，不进跑道 B。**

#### 跑道 B：样板域闭环（参考实现）——本项目选两个，不是一个

推荐并建议实际执行为**两个样板**：

| 样板分支 | 为什么选它 | 它把哪些"难制度"一次性跑通 |
| --- | --- | --- |
| `feat/logistics-material-loop`<br>后勤-物资领用 | 同时含 **SELF 写入**（applicantId 强制）、**workflow 审批双校验**、**asset CAS 并发点 B1-3**、**40903 实时值回传** | 归属型写入 + 并发扣减 + 冲突返回体三段式 |
| `feat/party-room-booking-loop`<br>党政-会议室预约 | 同时含 **组织型范围**（SELF/GRADE/ALL）、**space 单向校验 40901/40902**、**占用矩阵脱敏**、**`hasOccupancyDetail` 布尔** | 跨级组织型 + 冲突回显脱敏 + 时间口径 |

理由：六域其余接口基本是这两类的组合（德育/科教/体育 = "关系型 or 本班" + "space/asset 之一"）。**两个样板跑通，复制成本与风险都最小；只做一个样板，另一类必在复制期暴露。**

- 样板域的 PR **必须逐接口登记**（至少一个 ad-hoc 表格，列出：路由 → 归属类型 → 所需范围 → `@DataScope()` 装饰位置 → 服务端校验落点文件行 → 越权返回码），此表随后成为 docs/02 §3.3 的补全素材。
- 样板域合入后可打一个**轻量里程碑标记**（可选）：
  `git tag loop/logistics-material-v1 <merge-commit>`——复制时可用 `git diff loop/logistics-material-v1..HEAD` 看偏差。复制全部完成后删除，不留垃圾 tag。

#### 跑道 C：复制扩展（copy）——成批推进，但绝不能"一次合完"

分支名一律带 `copy-` 前缀：`feat/copy-moral-leave`、`feat/copy-science-lab`、`feat/copy-sport-equipment`……**一眼能看出是复制产物。**

- **禁止 `feat/all-domains` 一次性六域大分支；禁止把多个域放进同一个 PR。**
- **每批次最多一个域的一组同场景接口**，合一个、抽查一个、CHANGELOG 记一条。
- 复制类 PR 的 Review 重心不是"业务逻辑对不对"（那部分已被样板验证），而是**「复制污染」三类偏差**，必须逐条勾：
  1. **归属类型被换错**：本该 ORGANIZATION 的写成 SELF；本该 RELATIONSHIP（家长-子女）的写成 SELF 了事。
  2. **样板身份串味**：把样板的 `assetType` / 按钮权限点硬编码带了过来（典型事故：`BTN-MAT-APPLY` 被复制到体育器材借用接口，导致 asset 域隔离 B5 失效；实验器材复制成 `MATERIAL`）。
  3. **scope 照抄**：把样板的 `@DataScope({ scope: 'GRADE' })` 一字不改复制到本应 `SELF` 的接口（或反过来），造成低范围角色看到不该看的数据。

> 一句话：**样板域的 Review 逐行读逻辑；复制域的 Review 逐行比对"和样板的差异"是否都合理。**

### 1.6 迁移文件的时间戳冲突（Prisma 特有，必须预防）

多人并行开发时，`prisma migrate dev` 生成的时间戳前缀可能撞车或顺序错乱。

- 涉及 schema 的分支，在生成迁移**之前**先 `git pull --rebase origin develop`，再执行迁移命令。
- 合入后发现自己的迁移时间戳早于 develop 上已有的迁移 → **重命名自己的迁移目录时间戳并重跑 `prisma migrate diff` 校验**；此操作只允许对自己的**尚未合入**的迁移做。
- **禁止修改已合入 `develop` 的历史 migration 内容**（对应 docs/02 §1.4「禁止手工改库」）。有错就用新的迁移修正。
- 禁止出现 `prisma db push` 进 `develop`（它绕过迁移脚本，是审核必拦项，见 §四 E4）。

## 二、Conventional Commits 规范

### 2.1 格式

```
<type>(<scope>): <subject>
<空行>
<body>
<空行>
<footer>
```

- **subject**：祈使句、不加句号、≤72 字符（中文按 ≤36 字）。禁止 `修改代码` / `fix bug` / `更新` / `临时` / `wip` 这类零信息标题——合并时会被直接退回。
- **body（必写）**：「改了什么 + **为什么**」。**权限相关提交还必须在 body 写明「服务端校验落点（文件路径）」**，这是日后审计与门禁抽查的索引。
- **footer**：`Refs: docs/02 §1.5`、`Refs: docs/04 §4.2 判定算法 C`；破坏性变更用 `BREAKING CHANGE: ...`。

### 2.2 type 清单与适用场景

| type | 适用场景 | 本项目边界 |
| --- | --- | --- |
| `feat` | 新增能力（新接口 / 新页面 / 新机制） | 新路由必须同 commit 带 `@DataScope()` 声明；新字典/新菜单/新角色同步 docs/03 |
| `fix` | 修缺陷（含越权、口径错、状态机错、并发错） | **越权类一律 `fix`，不得降级成 `refactor`** |
| `docs` | 只改文档，不改行为 | docs/01~18 的修订、口径补写 |
| `refactor` | 代码整理，**对外行为与判定语义完全不变** | 若改动触碰 `docs/04 §4.2 A–E` 判定语义或 `ScopeQueryBuilder` 范围条件 → 必须改判为 `fix(perm):`（见下方裁决） |
| `perf` | 性能优化，行为不变 | 大屏聚合、排课引擎调优 |
| `test` | 只加/改测试 | 越权场景（docs/04 §六）与并发用例（docs/02 §4.1）的固定测试**优先独立成 commit**，便于门禁 6 单独取用 |
| `chore` | 不产生产品行为的杂项：脚手架、依赖、种子数据、仓库配置 | `chore(prisma):` = 迁移 / 种子；`chore(repo):` = .gitignore / CI / 脚本 |
| `build` | 构建链路：打包、Docker、依赖大版本 | Dockerfile / compose / Vite 配置 |
| `ci` | CI/流水线、lint 规则 | ESLint 自定义规则（含封堵裸 SQL 的规则）改动用此 |
| `revert` | 撤销已合入提交 | 必须写明被 revert 的提交标题与原因 |

**三条易踩裁决：**

1. **权限判定改动不得用 `refactor`。** docs/04 §4.2 的 A–E 判定算法、角色保存校验器、DataScopeGuard 运行时兜底（docs/02 §3.4）任一改动 → `feat(perm)` 或 `fix(perm)`，并在 body 指明改的是哪个字母分支（A/B/C/D/E）。理由：它是**安全语义变更**，混在 refactor 里会导致抽查检索不到。
2. **migration 与 schema 必须同 commit。** 禁止 `schema.prisma` 一个 commit、`migration.sql` 另一个（两者不一致会造成本地能跑、复制新校就崩）。
3. **一个 commit 一个 type。** 功能 + 顺手改 bug → 拆成 `feat` + `fix` 两个提交。

### 2.3 scope 取值清单（按 docs/02 §1.6 分层，闭集）

| 层 | scope | 覆盖范围 |
| --- | --- | --- |
| **平台层** | `auth` | 认证 / JWT / 账号状态（docs/03 C8） |
| | `rbac` | 用户 / 角色 / 菜单 / 部门 / 三级数据范围（含角色保存校验器） |
| | `dict` | 数据字典 M0505 |
| | `flow-template` | 流程模板 M0507 |
| | `message` | 消息中心 M0105 / M0506 / outbox |
| | `space` | 统一场地 + 占用 + 占用矩阵 + SlotOccupancy 判定器 |
| | `asset` | 统一资产台账 + 域隔离 + 借还 + 库存 |
| | `term` | 学期 / 周次上下文（时间口径） |
| | `alert` | 超期提醒 C10 |
| | `jobs` | BullMQ / 定时任务基座 |
| | `ai` | AiGateway / 供应商适配 / PII 脱敏层 |
| | `prisma` | schema.prisma、迁移、种子（不属平台层，特指数据层元数据） |
| | `common` | Guard / 拦截器 / **ScopeQueryBuilder** / PIIFilter 等公共件（**非权限判定算法本身**） |
| **横切层** | `workflow` | 审批流程实例引擎（docs/07） |
| | `dashboard` | 数据大屏聚合与下钻 M15 |
| **业务域层** | `logistics` | 后勤域 M02–M04 |
| | `academic` | 教务域 M06–M08（含排课引擎 Worker） |
| | `moral` | 德育域 M09–M11 |
| | `party` | 党政办域 M12 |
| | `science` | 科教域 M13 |
| | `sport` | 体育域 M14 |
| **权限专项** | `perm` | 跨层权限机制改动统一收口于此（fail-closed 三层 / docs/04 §4.2 判定算法 / 40301–40304·40901–40904 语义 / 角色硬约束） |
| **工程** | `repo` | 仓库级配置：.gitignore / CI / 脚本 / 依赖 / CHANGELOG |
| | `web` | 前端**工程基础设施**（路由基座 / HTTP 封装 / Token / 动态菜单）；**页面级业务改动一律用该页面所属域的 scope**（教务页面写 `academic`，不得偷懒写 `web`） |
| | `deploy` | nginx / compose / 部署脚本 |
| | `docs` | 文档自身整改 |

**scope 规则：**

1. **闭集**：不在上表的（`server` / `backend` / `api` / `domains` / 中文 / 个人花名）一律退回，重新选择或拆 commit。
2. **禁止 `feat(domains)` / `feat(all)` 这种笼统 scope**——它正是权限抽查无法定位责任接口的根因（见 §1.5 跑道 A 的例外才是允许的整体改动）。
3. commit scope ≠ 权限 scope：前者标识改动位置，后者是 `@DataScope({ scope: 'SELF'|'GRADE'|'ALL' })` 的运行值（docs/03 §2.1⑤：只有三级，不新增第四级）。两者不可混写、不得互相推断。
4. **`perm` 的价值**：门禁 5 / 6 的权限抽查从 `git log --grep` 或 `git log --oneline -- apps/server/src/common ':(exclude)**/*.spec.ts'` 之外，还应有单入口：`git log --oneline --grep='^(feat\|fix)\(perm\)'`。**所有涉及 fail-closed 三层、判定算法、错误码语义的提交必须落 `perm`**，这是一条给抽查者、审题者、未来维护者走的唯一线索。

### 2.4 破坏性变更标注

属于 BREAKING 的情形（本项目口径）：**错误码语义变化**、**API 契约字段增删/改名**、`templateKey` 取值集变化、`@DataScope` 的必填项变化、`assetType`/`spaceType` 码值变化、新增/删除预置角色 `R-*`。

```
feat(perm)!: 单条越权统一收敛为 40304

BREAKING CHANGE: 原先「越权单条查询」返回 403 DATA_SCOPE_DENIED，现收敛为 40304
RESOURCE_NOT_FOUND（防枚举，docs/04 §4.3）。前端 api/types.ts 的 BizErrorCode 需同步；
旧行为 GET /api/leave/requests/:id（越权）由 403 变 40304。
Refs: docs/02 §3.2, docs/04 §4.3
```

### 2.5 本项目真实场景提交示例

**① 权限机制立柱**

```
feat(perm): 新增 @DataScope 装饰器与启动期缺声明校验

实现 fail-closed 第②层（docs/02 §1.5）：新增 @DataScope() 声明「归属类型 + 所需范围」，
Bootstrap 阶段反射扫描全部 Controller 方法，凡注入 PrismaService 且未声明 @DataScope 的数据读写
接口一律 throw，令应用拒绝启动；运行时由 DataScopeGuard 按 docs/04 §4.2 A-E 判定。

服务端校验落点：
- apps/server/src/common/decorator/data-scope.decorator.ts  （声明）
- apps/server/src/common/bootstrap/data-scope-scanner.ts    （启动期反射扫描，fail-closed）
- apps/server/src/common/guard/data-scope.guard.ts          （运行时判定）

自测证据：临时摘掉 GET /api/procurement/projects 的装饰器 → bootstrap 失败并打印缺失清单。
```

## 三、CHANGELOG 机制

### 3.1 文件与结构

根目录 `CHANGELOG.md`，Keep a Changelog 格式 + SemVer 版本。本项目在标准分组之上**强制增设 `Security` 分组**。

```markdown
# 变更日志

## [Unreleased]

### Added
### Changed
### ⚠ Security        ← 本项目强制必设
### Fixed
### Deprecated / Removed

## [0.1.0] - YYYY-MM-DD
### Added
- feat(logistics): 物资领用申请与审批全链路（首个样板域闭环）
### ⚠ Security
- feat(perm): @DataScope 装饰器 + 启动期缺声明校验（fail-closed 第②层，docs/02 §1.5）
- fix(space): 占用矩阵不再回传班级/教师身份字段（docs/02 §3.2 越权红线）
### Fixed
- fix(asset): 跨域借用未做 assetType × 权限点双重校验（docs/04 §3.9 B5）
```

版本节律（与阶段对齐，便于复制包取版本）：

| 版本 | 含义 |
| --- | --- |
| `0.1.0` | 跑道 A 立柱合入 + 跑道 B 两个样板域闭环（docs/02 §1.5 三层可验证） |
| `0.2.0` ~ `0.5.0` | 跑道 C 逐域复制批次，每域一个 minor 或按批次定 |
| `1.0.0` | 六域 + 大屏 + 消息中心全部贯通，通过门禁 6 |

### 3.2 type → 分组的对应关系

| commit type | 落入分组 | 例外 |
| --- | --- | --- |
| `feat` | Added | scope 为 `perm` 或改动错误码/判定算法 → **同时**记入 Security |
| `fix` | Fixed | 越权 / 脱敏 / 权限判定类 fix → **同时**记入 Security（本应在 Security 用红色粗体呈现） |
| `refactor` / `perf` / `test` | 通常不记 | 若导致对外行为变化（例如数据出口从业务直连改为 ScopeQueryBuilder）→ Changed |
| `docs` | 不记 | 若改动的是对外契约描述且行为已变 → 随对应记 `Changed` |
| `chore` / `build` / `ci` | 不记 | 影响部署形态 / 依赖大版本 → Changed（并注明对复制的影响） |
| `revert` | Fixed 或 Changed（注明被撤销项） | Security 条目的撤销必须在 Security 写明 |
| 任何含 `BREAKING CHANGE` 的提交 | Changed + 顶部挂 `### ⚠ Breaking` | 必须写明前端需同步的文件 |

### 3.3 维护规则

1. **随合并更新，不攒到发布前。** 攒到发布前补 = 「Security 条目必漏」的充分条件**（见 §七 Top 违规 7）。
2. **一条目的粒度 = 一个分支一件事**，条目末尾挂文档指针（`docs/04 §4.2 C`）。
3. **Security 条目是权限抽查的取数入口**：门禁 5 / 6 直接 `grep '^### ⚠ Security' -A 30 CHANGELOG.md` 拉本次全部安全相关改动，逐条比对 §四 清单。若某条 `@DataScope` 改动进了 git log 但没进 Security 分组 → 抽查判不通过。
4. 版本号与 `release/*` 分支名、tag `vX.Y.Z` 三者必须一致。

### 5.4 代码落地后的前几个提交（建议顺序）

架构骨架落地时**不要一把梭**，按跑道 A 拆成有序提交，每个提交只做一件事：

| 序 | 提交（建议） | 内容 |
| --- | --- | --- |
| 1 | `chore(repo): 新增版本控制规范与 CHANGELOG 骨架` | 本文档 + CHANGELOG（若未随首提交进） |
| 2 | `build(repo): 初始化 NestJS 应用骨架与 TS/ESLint 配置` | `src/main.ts`、`app.module.ts`、ESLint/tsconfig 落地（能起空服务即可） |
| 3 | `ci(repo): 新增 ESLint 裸查询封堵规则` | 自定义规则：`prisma.$queryRaw` / 绕过 `ScopeQueryBuilder` 直查 → error |
| 4 | **`feat(perm): 新增 @DataScope 装饰器与启动期缺声明校验`** | fail-closed 第②层；附"摘掉装饰器 → bootstrap 失败"证据 |
| 5 | **`feat(perm): 注册 AuthGuard / PermissionGuard 为全局 Guard`** | fail-closed 第①层 |
| 6 | **`feat(common): 新增 ScopeQueryBuilder 作为数据层唯一出口`** | fail-closed 第③层 |
| 7 | `chore(prisma): init 迁移基线（六域对象 + 12 角色种子）` | docs/02 §1.4 要求的全对象 init + 幂等 seed |
| 8 | `feat(logistics): 后勤-物资领用单场景闭环` | 跑道 B 样板一（PR 需附逐接口登记表） |
| 9 | `feat(party): 党政-会议室预约单场景闭环` | 跑道 B 样板二（含 40901/40902 + 占用矩阵脱敏） |
| 10+ | `feat/copy-*` 系列 | 跑道 C，每域一个 PR，逐个抽查 |

> 第 3、4、5 项的先后顺序**不可颠倒**：先有 lint 封堵，再补装饰器与全局 Guard，最后才有第 6 项的数据层出口；倒过来会出现"先写了业务再补规矩"的空窗期，那正是漏洞产生的时段。

## 七、高危易违规清单（开发阶段重点盯）

按"发生的概率 × 后果严重度"排序。**Top 1–4 是权限类，发现即阻断。**

| 排名 | 条款 | 为什么极易被违反 | 盯法 |
| --- | --- | --- | --- |
| **1** | §4 A1/A2 **`@DataScope()` 漏声明** | 复制五域时新 Controller 不断新增，"忘加"是缺省态；更危险的是启动期扫描被临时绕过（"先把服务跑起来再说"），一旦绕过就再没人补回来 | 每次 PR 只看两件事：`controller.ts` 清单逐个过 + bootstrap 失败证据。**发现缺一个装饰器或扫描被关 → 阻断** |
| **2** | §4 B1 **为写并发而绕过 `ScopeQueryBuilder`** | C9 的 CAS / 部分唯一索引确实不好用构造器表达，于是业务代码里手写一条 `$executeRaw`——这条缝一旦开，后面所有"不好表达"都会往里钻 | 裸 SQL 必须集中在 `platform/concurrency`；任何 `eslint-disable` 新增一律阻断并要求书面理由 |
| **3** | §4 C1/C2 **前端便利滑坡** | `templates.ts` 里加一个 `if (role === 'GRADE')` 比改服务端聚合快得多；"临时过渡"基本都会永久化 | CI/PR 里直接 grep `if (role ==`；命中即驳回。同理"前端拉全量再过滤" |
| **4** | §4 D1/D2 **冲突提示回显他人姓名班级** | 为了"体验好"把 `occupiedBy` 补全；这类改动在 UI 上看起来是改善，实质是越权 | 任何涉及 `conflict.*` / `occupancies` 的改动必进 D 区抽查；要求附"用 SELF 范围账号触发 40901 的返回体截图/报文" |
| 5 | §2.3 **一把梭提交 `feat(domains): 六域联调`** | 赶工时最自然的产物 | 政策：标题写不下一个场景 → 拆 PR；`scope` 不在闭集 → 驳回 |
| 6 | §1.5 **复制污染**（照抄样板 scope / assetType / 按钮点） | 因为是"复制",人不会重读每一行；尤其 `BTN-MAT-APPLY` 串到体育器材、 ORGANIZATION 写成 SELF | 复制 PR 的 Review 强制做"与样板域的差异比对"，并把差异写进 PR 描述 |
| 7 | §3.3 **CHANGELOG 攒到发布前补** | 发布前补必然漏 `Security` 条目，而 Security 正是门禁 5/6 的取数入口 | merge checklist 里 CHANGELOG 与代码同 PR；漏即退回补，不单独开"补日志"PR |
| 8 | §1.6 / §4 E **migration 与 schema 不同 commit、或改了已合入的历史迁移** | 本地跑通就以为没事；复制到新校时才发现迁移顺序错 | E1/E2/E4 逐条勾；`db push` 出现在 develop → 阻断 |
| 9 | §5.3 **把 lockfile 忽略掉（或反过来把 `.env` 提交上来）** | .gitignore 模板随手抄；这两条错误都会直接毁掉"复制这一核心策略"（前者不可复现，后者泄露口令） | 首提交时逐一核对 §5.3 的"绝不出现"清单 |
| 10 | §1.4 **`--force` 推共享分支 / rebase 已推送分支** | 冲突解决习惯性动作 | `develop`/`main` 只允许 ff 合入；事后补救一律 revert，不改写历史 |
